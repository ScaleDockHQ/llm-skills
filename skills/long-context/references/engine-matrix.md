# Long Context: per-engine flag matrix

> Verified against vLLM v0.31.0 (docs: context_extension, context_parallel_deployment; source: vllm/config/model.py, scheduler.py, parallel.py, engine/arg_utils.py), SGLang v0.5.21 (docs: server_arguments), TensorRT-LLM v1.2.1 (docs: long-sequence, parallel-strategy; source: llm_args.py), llama.cpp build b11556 (tools/server README, common/arg.cpp), TensorFold v1.0.7 (README), Ollama v0.40.3 (docs.ollama.com context-length, faq, modelfile), Qwen3-30B-A3B model card (Processing Long Texts), 2026-10-11

Every flag below was read in the upstream source or docs named above on the date above. Anything not found is marked "(unverified)" or "not documented".

## Context length and KV capacity

| Engine       | Flag / config                                                                                                                      | Default                                                                                                                                            | Notes                                                                                                                                                                                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| vLLM         | `--max-model-len N`                                                                                                                | derived from the model config (`max_model_len` field defaults to none, then `_get_and_verify_max_len`)                                             | Sets the request limit and the KV pre-allocation. The docs call it "the new maximum sequence length after extension (original x factor)". Startup logs the KV capacity.                                                                                                                               |
| SGLang       | `--context-length N`                                                                                                               | none: "will use the value from the model's config.json"                                                                                            | Overrides the window. Startup logs the token capacity.                                                                                                                                                                                                                                                |
| TensorRT-LLM | `max_seq_len` (LLM API / `trtllm-serve` config), `max_input_len`, `max_num_tokens`                                                 | `max_seq_len` none; `max_num_tokens` 8192                                                                                                          | `max_num_tokens` should be a multiple of the KV block size `tokens_per_block` (default 64) when chunked prefill is on.                                                                                                                                                                                |
| llama.cpp    | `-c`, `--ctx-size N` (`LLAMA_ARG_CTX_SIZE`)                                                                                        | 0 (loaded from the model)                                                                                                                          | The context is shared across `-np` slots unless the unified KV buffer is used. `--kv-unified-per-slot N` sizes the shared pool as `n_parallel x N`. With `--fit on` (default) unset values may be reduced to fit memory; `-c 0` disables that reduction, and `-fitc` sets the minimum (default 4096). |
| TensorFold   | `--context N`                                                                                                                      | engine and family specific; Qwen3.8-27B defaults to 32,768 and takes up to 262,144                                                                 | Bounds prompt plus reply. `--context 0` is family-specific; use a positive number for GLM. Startup prints the fitted capacity. `GET /v1/models` shows `context_length` and `max_model_len`.                                                                                                           |
| Ollama       | `OLLAMA_CONTEXT_LENGTH` (server env), `PARAMETER num_ctx N` (Modelfile), `options.num_ctx` (API), `/set parameter num_ctx N` (CLI) | docs disagree: context-length page says by VRAM (under 24 GiB: 4k; 24-48 GiB: 32k; 48 GiB or more: 256k); FAQ says 4096; Modelfile table says 2048 | Check the real value with `ollama ps` (CONTEXT column). The docs advise at least 64000 for agents, search and coding tools. Larger context raises memory; avoid CPU offload (see the `PROCESSOR` column). `OLLAMA_NUM_PARALLEL` (default 1) multiplies RAM by `OLLAMA_CONTEXT_LENGTH`.                |
| ExLlamaV3    | TabbyAPI `model.max_seq_len`, `model.cache_size`                                                                                   | (unverified)                                                                                                                                       | Names come from this repo's `self-hosted-llms` reference, not re-read upstream on this date. Read the TabbyAPI config before use.                                                                                                                                                                     |

## RoPE and YaRN scaling (changes numerics: gate it)

| Engine       | How                                                                                                                                                                                                                | Notes                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| vLLM         | `--hf-overrides '{"rope_parameters": {"factor": 4.0, "original_max_position_embeddings": 32768, "rope_theta": 1000000, "rope_type": "yarn"}}' --max-model-len 131072`                                              | From the vLLM docs example for Qwen3-0.6B. `--rope-scaling` "used in older versions of vLLM is no longer supported". Keys depend on `rope_type` (`yarn`, `linear`, `dynamic`); see the Hugging Face Transformers RoPE docs. Always set `--max-model-len` to the extended length.                                                                                                                                        |
| SGLang       | `--json-model-override-args '{"rope_scaling":{"rope_type":"yarn","factor":4.0,"original_max_position_embeddings":32768}}'` plus `--context-length N`                                                               | Form taken from the Qwen3 model card. `--json-model-override-args` default is `{}`. Whether the Qwen-card key `rope_scaling` or the newer `rope_parameters` is right for your SGLang version is (unverified): check the startup log.                                                                                                                                                                                    |
| TensorRT-LLM | edit the checkpoint's `config.json` `rope_scaling`                                                                                                                                                                 | Not covered by the long-sequence or attention pages at v1.2.1. Exact keys and supported rope types are (unverified); read the model support page for your architecture.                                                                                                                                                                                                                                                 |
| llama.cpp    | `--rope-scaling {none,linear,yarn}`, `--rope-scale N`, `--rope-freq-base N`, `--rope-freq-scale N`, `--yarn-orig-ctx N`, `--yarn-ext-factor N`, `--yarn-attn-factor N`, `--yarn-beta-slow N`, `--yarn-beta-fast N` | `--rope-scaling` "defaults to linear unless specified by the model". `--rope-scale N` expands context by N (it sets the frequency scale to 1/N). `--yarn-orig-ctx` defaults to 0, the model's training context. `--yarn-ext-factor` 0.0 means full interpolation. Qwen3 card example: `--rope-scaling yarn --rope-scale 4 --yarn-orig-ctx 32768` (add `-c 131072`). If the config.json was edited, regenerate the GGUF. |
| TensorFold   | none documented                                                                                                                                                                                                    | The README lists `--context` only. Use the context that the qualified model supports.                                                                                                                                                                                                                                                                                                                                   |
| Ollama       | none documented                                                                                                                                                                                                    | Not in the Modelfile reference at v0.40.3. Use a model tag that ships the long window.                                                                                                                                                                                                                                                                                                                                  |
| ExLlamaV3    | (unverified)                                                                                                                                                                                                       | Not read upstream on this date.                                                                                                                                                                                                                                                                                                                                                                                         |

Vendor guidance to follow (Qwen3 model card): all notable frameworks implement static YaRN, so the factor is constant regardless of input length and can hurt short texts; add it only when long context is required, and size the factor to the typical length (for example 2.0 if typical contexts are 65,536 tokens on a 32,768 native model).

| ------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| vLLM         | `--enable-chunked-prefill`, `--max-num-batched-tokens N`, `--long-prefill-token-threshold N` | chunked prefill on in the config class; `max_num_batched_tokens` 2048 in the config class, but the real default is chosen per hardware and usage context in `create_engine_config`; threshold 0 | Prefill is chunked by the remaining `max_num_batched_tokens`. ## Sliding window and chunked attention

| Engine       | Flag / config                                                                            | Notes                                                                                                                                                                                                                                                                      |
| ------------ | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| vLLM         | `--disable-sliding-window` (default false)                                               | Caps the model at its sliding window length when set (per source docstring semantics, (unverified) wording). A hybrid KV cache manager design doc covers models mixing full and sliding-window layers.                                                                     |
| SGLang       | `--swa-full-tokens-ratio R` (0 to 1), `--disable-hybrid-swa-memory`                      | Ratio of sliding-window-layer KV tokens to full-layer KV tokens. Hybrid SWA memory is on unless disabled.                                                                                                                                                                  |
| TensorRT-LLM | `KvCacheConfig.max_attention_window` (a `list[int]`, per layer, repeated to fill layers) | Cyclic KV cache keeps only the last N tokens. Allocation still follows the largest value. Not compatible with beam search. `attention_chunk_size` (read from model config) enables chunked attention for Llama 4 with the TRTLLM attention backend, context requests only. |
| llama.cpp    | `--swa-full` (default false)                                                             | "use full-size SWA cache". Off by default, so the smaller sliding-window cache is used; the help text links PR 13194 for the trade-offs, which this skill did not re-read.                                                                                                 |

Sliding-window attention is a model property. Do not override a model's window to "extend" it unless the vendor documents the setting; it changes numerics.

## Context parallelism

| Engine                        | Flag / config                                                                                                                                                | Default  | Constraints                                                                                                                                                                                                                                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| vLLM decode CP                | `-dcp`, `--decode-context-parallel-size N`, `--dcp-kv-cache-interleave-size N`                                                                               | 1, 1     | Shards the KV cache along tokens. Size must be in `[1, tp_size / kv_heads]`. It does not add GPUs; it cuts KV duplication. Larger values cut duplication but raise communication. Supported for MLA and GQA models. Docs case study: DeepSeek-R1 (1 KV head with MLA) at TP 8 duplicates KV 8 times, so `-dcp 8` removes it. |
| vLLM prefill CP               | `-pcp`, `--prefill-context-parallel-size N`                                                                                                                  | 1        | Splits one long prompt's prefill across ranks. Expands the process world size and does not increase the KV shard count. The docs say both approaches are "under active development".                                                                                                                                         |
| SGLang                        | `--attn-cp-size N` (`--attention-context-parallel-size`), `--dcp-size N` (`--decode-context-parallel-size`), `--dcp-comm-backend` (`ag_rs`, `a2a`, `fi_a2a`) | 1, 1     | `--dcp-size` is documented for MLA models (the arguments page links a "Decode Context Parallelism" page). `--dcp-comm-backend` unset resolves by hardware.                                                                                                                                                                   |
| TensorRT-LLM                  | `cp_size`, `cp_config` (parallel config)                                                                                                                     | 1, empty | Docs list Context Parallel and a Helix feature page; exact YAML keys for serving are (unverified) beyond `cp_size` and `cp_config` in `llm_args.py`.                                                                                                                                                                         |
| llama.cpp, TensorFold, Ollama | not documented                                                                                                                                               | n/a      | n/a                                                                                                                                                                                                                                                                                                                          |

## Quality caveats (all engines)

- Extended RoPE is an approximation. Validate at the lengths you will use, not only at the maximum.
- Static scaling affects short prompts. Test short prompts before and after.
- KV-cache quantization (`kv-cache-quantization` skill) compounds with long context. Gate them together.
- Prefix and prompt caches (`prefix-aware-routing` skill) can hide a bad extension in benchmarks that reuse the same prefix. Disable caching for the gate.
