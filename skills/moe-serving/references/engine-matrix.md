# MoE Serving: per-engine flag matrix

> Verified against vLLM v0.31.0 (docs: expert_parallel_deployment, moe_kernel_features; source: vllm/config/parallel.py, kernel.py, offload.py), SGLang v0.5.21 (docs: expert_parallelism, server_arguments), TensorRT-LLM v1.2.1 (docs: parallel-strategy; source: llm_args.py), llama.cpp build b11556 (tools/server README, common/arg.cpp), TensorFold v1.0.7 (README), Ollama v0.40.3 (docs.ollama.com modelfile, faq), ExLlamaV3 v1.6.1 (README), KTransformers v0.7.1 (README), 2026-10-11

Every flag below was read in the upstream source or docs named above on the date above. Defaults are the upstream defaults at that version. Anything not found is marked "(unverified)" or "not documented".

## vLLM v0.31.0

| Need                     | Flag / config                                                                                                                                                                 | Default                                         | Constraints and notes                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Enable EP                | `--enable-expert-parallel` (`-ep`)                                                                                                                                            | off                                             | EP size is computed, not set: `TP x DP` (source also folds in prefill context parallel). Without it MoE layers use tensor parallel. Attention stays TP, or is replicated across DP ranks when `TP=1`.                                                                                                                                                                                                                    |
| Data parallel attention  | `--data-parallel-size N`, `--tensor-parallel-size N`                                                                                                                          | 1, 1                                            | EP is "typically coupled with DP". Single-node example in the docs: `--tensor-parallel-size 1 --data-parallel-size 8 --enable-expert-parallel`.                                                                                                                                                                                                                                                                          |
| All-to-all backend       | `--all2all-backend`                                                                                                                                                           | `allgather_reducescatter`                       | Options in source: `allgather_reducescatter`, `deepep_high_throughput`, `deepep_low_latency`, `mori_high_throughput`, `mori_low_latency`, `moonep`, `nixl_ep`, `flashinfer_nvlink_one_sided`, `flashinfer_nvlink_two_sided`. DeepEP backends need DeepEP and DeepGEMM installed (docs link the repo's `tools/ep_kernels`). The docs say DeepEP kernels target disaggregated serving and may be slow for mixed workloads. |
| Expert placement         | `--expert-placement-strategy`                                                                                                                                                 | `linear`                                        | `linear` or `round_robin`. Round robin can help balance grouped-expert models with no redundant experts.                                                                                                                                                                                                                                                                                                                 |
| EPLB                     | `--enable-eplb`                                                                                                                                                               | off                                             | Collects load statistics each forward pass and rebalances periodically.                                                                                                                                                                                                                                                                                                                                                  |
| EPLB tuning              | `--eplb-config '{...}'` or `--eplb-config.<key>`                                                                                                                              | see keys                                        | Keys and defaults: `window_size` 1000, `step_interval` 3000, `num_redundant_experts` 0, `log_balancedness` false, `use_async` true, `policy` "default", `communicator` null (auto; `torch_nccl`, `torch_gloo`, `pynccl`, `nixl`). Async EPLB needs `policy: default` and rejects `torch_nccl`/`pynccl` communicators (source validators).                                                                                |
| EPLB memory              | n/a                                                                                                                                                                           | n/a                                             | Redundant experts occupy VRAM: `NUM_MOE_LAYERS x BYTES_PER_EXPERT x (TOTAL + REDUNDANT) / EP_RANKS`. Docs: about 2.4 GB for DeepSeek-V3 with one redundant expert per rank. Docs suggest 32 redundant experts at large scale.                                                                                                                                                                                            |
| Overlap                  | `--enable-dbo`                                                                                                                                                                | off                                             | Dual Batch Overlap hides all-to-all behind compute. `--async-scheduling` is marked experimental in the docs.                                                                                                                                                                                                                                                                                                             |
| MoE kernel backend       | `--moe-backend`                                                                                                                                                               | `auto`                                          | Options in source include `triton`, `batched_triton`, `deep_gemm` (FP8 block-quantized only), `cutlass`, `flashinfer_trtllm`, `flashinfer_cutlass`, `flashinfer_cutedsl` (FP4 only), `marlin`, `aiter`, plus newer experimental ones. Read `vllm serve --help=KernelConfig` for the installed list. Quantized kernels change numerics.                                                                                   |
| Multi-node               | `--data-parallel-size`, `--data-parallel-size-local`, `--data-parallel-start-rank`, `--data-parallel-address`, `--data-parallel-rpc-port`, `--headless`, `--api-server-count` | n/a                                             | One command per node. Node 1 serves requests; others run `--headless`. `--data-parallel-start-rank` equals the sum of earlier nodes' local DP sizes. On InfiniBand set `GLOO_SOCKET_IFNAME=eth0` to avoid init hangs.                                                                                                                                                                                                    |
| Expert CPU offload (UVA) | `--cpu-offload-gb G` with `--cpu-offload-params experts`                                                                                                                      | 0 (off)                                         | Per GPU, needs a fast CPU-GPU link, weights are read from CPU memory on every forward pass. With the params set empty, parameters are offloaded non-selectively until the budget is reached. Param names match exact dotted segments (`experts` matches, `expert` does not).                                                                                                                                             |
| Layer prefetch offload   | `--offload-backend prefetch`, `--offload-group-size`, `--offload-num-in-group`, `--offload-prefetch-step`, `--offload-params`                                                 | backend `auto`; num-in-group 1; prefetch-step 1 | `auto` picks prefetch if group size is above 0, UVA if `cpu-offload-gb` is above 0. Group 8 with num-in-group 2 offloads layers 6, 7, 14, 15, and so on.                                                                                                                                                                                                                                                                 |
| Benchmark helpers        | `VLLM_MOE_ROUTING_SIMULATION_STRATEGY=uniform_random`, `VLLM_RANDOMIZE_DP_DUMMY_INPUTS=1`                                                                                     | unset                                           | Balances routing so a benchmark does not measure skew. Never use for quality evals.                                                                                                                                                                                                                                                                                                                                      |

Troubleshooting strings from the vLLM docs: `non-zero status: 7 cannot register cq buf` (set `ulimit -l unlimited` on host and pods); `init failed for transport: IBGDA` (InfiniBand GDA kernel modules missing; run the repo's `tools/ep_kernels/configure_system_drivers.sh` and reboot); NVSHMEM peer disconnect (usually networking; on Kubernetes pods need `hostNetwork: true` and privileged).

LoRA on MoE models is covered by the `multi-lora-serving` skill.

## TensorRT-LLM v1.2.1

Configured with a YAML file passed with `--config` to `trtllm-serve` or `trtllm-bench` (the docs describe a config-flag alias note; check `trtllm-serve --help` for your install).

| Need                  | Config key                                             | Default              | Constraints and notes                                                                                                                                                                           |
| --------------------- | ------------------------------------------------------ | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tensor parallel       | `tensor_parallel_size`                                 | 1                    | Total TP group.                                                                                                                                                                                 |
| MoE TP / EP split     | `moe_tensor_parallel_size`, `moe_expert_parallel_size` | auto (-1 internally) | Product must equal `tensor_parallel_size`. Examples from the docs: TP only (8,8), EP only (TP 8, EP 8), hybrid (TP 4 x EP 2 on 8 GPUs).                                                         |
| Attention DP          | `enable_attention_dp`                                  | false                | DP attention replicates GEMM weights and partitions KV cache across requests.                                                                                                                   |
| MoE backend           | `moe_config.backend`                                   | `CUTLASS`            | Values in source: `CUTLASS`, `CUTEDSL`, `WIDEEP`, `TRTLLM`, `DEEPGEMM`, `VANILLA`, `TRITON`.                                                                                                    |
| MoE token chunking    | `moe_config.max_num_tokens`                            | none                 | Caps tokens per fused MoE call; larger inputs run in a loop.                                                                                                                                    |
| Load balancer         | `moe_config.load_balancer`                             | none                 | Wide-EP expert slots with offline EPLB (precomputed placement) or online EPLB. Docs advise starting with offline EPLB for known workloads. Examples live in the repo under `examples/wide_ep/`. |
| Determinism           | `moe_config.disable_finalize_fusion`                   | false                | Source says setting true recovers deterministic numerics with top-k above 2.                                                                                                                    |
| Low precision combine | `moe_config.use_low_precision_moe_combine`             | false                | NVFP4 only. Changes numerics.                                                                                                                                                                   |

Expert offload to CPU: not documented for TensorRT-LLM at this version.

## llama.cpp build b11556

| Need                           | Flag (env)                                                                             | Default      | Constraints and notes                                                                              |
| ------------------------------ | -------------------------------------------------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------- |
| All experts in RAM             | `-cmoe`, `--cpu-moe` (`LLAMA_ARG_CPU_MOE`)                                             | off          | Keeps all MoE expert weights on the CPU. Attention and shared tensors stay on the GPU with `-ngl`. |
| First N layers' experts in RAM | `-ncmoe N`, `--n-cpu-moe N` (`LLAMA_ARG_N_CPU_MOE`)                                    | 0            | "the first N layers". N must be 0 or more. Start high, lower it until VRAM is full.                |
| GPU cache for CPU experts      | `--moe-cache-mib N` (`LLAMA_ARG_MOE_CACHE_MIB`)                                        | 0 (disabled) | GPU cache in MiB for experts kept on the CPU; split across GPUs like layers (`--tensor-split`).    |
| Fine-grained placement         | `-ot`, `--override-tensor "<pattern>=<buffer type>,..."` (`LLAMA_ARG_OVERRIDE_TENSOR`) | none         | The `--cpu-moe` flags are shortcuts over this.                                                     |
| Dense FFN to RAM               | `-ncffn N`, `--n-cpu-ffn N`                                                            | n/a          | Dense models only; for MoE use `--n-cpu-moe`.                                                      |
| Auto fit                       | `-fit on\|off`, `-fitt` margins, `-fitc` (min ctx 4096)                                | `on`         | Adjusts unset arguments to fit device memory. Set `-c` explicitly if you need a fixed context.     |
| Draft model experts            | `--spec-draft-cpu-moe`, `--spec-draft-n-cpu-moe`                                       | off          | For the speculative draft model only.                                                              |

llama.cpp has no expert-parallel mode across GPUs in these docs (not documented); multi-GPU splits layers or tensors (`--tensor-split`).

## Sizing notes (arithmetic, not an upstream claim)

- Weights memory scales with total parameters. Speed scales with active parameters. A 30B-A3B model needs about 30B x bytes-per-weight of memory, not 3B.
- With EP, each rank holds `experts / EP_RANKS` experts plus replicated attention weights when `TP = 1`.
- With expert offload, decode speed is bounded by CPU memory bandwidth times the bytes read per token (active experts per layer). Measure instead of predicting.
