# Licenses for Fine-Tuning

> Verified against meta-llama/llama-models LICENSE files (Llama 3.1, 3.2, 3.3, 4), mistral.ai MRL-0.1, ai.google.dev/gemma/terms (last modified 2026-04-01) and ai.google.dev/gemma/apache_2, and Hugging Face model card license metadata for Qwen, Mistral, Gemma 4 and gpt-oss repos, 2026-10-11

This is an engineering checklist, not legal advice. Licenses change between model versions, and sometimes between sizes of the same release. Always read the license file in the exact repo and revision you train on, and involve legal for commercial distribution.

## Three things to check

1. **Base model license** — may you fine-tune, use commercially, and redistribute weights/adapters? Any naming, attribution, or acceptable-use obligations? User-count thresholds?
2. **Dataset licenses** — may the data be used for training (and commercially)? Attribution or share-alike terms? Personal data and consent?
3. **Output/teacher terms** — if training data was generated by another model or API, do that provider's terms allow using outputs to train models?

## Where to find the license

```bash
curl -s https://huggingface.co/api/models/<org>/<model> | jq -r '.cardData.license, .cardData.license_name, .cardData.license_link, .gated'
hf download <org>/<model> LICENSE --local-dir /tmp/lic-check 2>/dev/null; ls /tmp/lic-check
```

`license: other` means a custom license: read `license_name` / `license_link`. `gated: manual|auto` means you must accept terms on the Hub (your `$HF_TOKEN` must belong to an account that accepted).

## Model families (high level; verify per repo)

**Meta Llama (Llama 3.1 / 3.2 / 3.3 / 4 Community License).** Custom license, gated on the Hub. Clauses that matter for fine-tunes, quoted from the LICENSE files in meta-llama/llama-models:
- If you distribute Llama Materials or derivatives, "provide a copy of this Agreement" and "prominently display 'Built with Llama'" on a related website, UI, blog post, about page, or product documentation.
- "If you use the Llama Materials or any outputs or results of the Llama Materials to create, train, fine tune, or otherwise improve an AI model, which is distributed or made available, you shall also include 'Llama' at the beginning of any such AI model name." So a distributed fine-tune is named e.g. `Llama-<something>`.
- A separate license is required if your (or your affiliates') products had more than 700 million monthly active users in the preceding calendar month.
- Use is subject to the Acceptable Use Policy (`USE_POLICY.md` next to each LICENSE).

**Google Gemma.** Gemma models before Gemma 4 are under the Gemma Terms of Use (ai.google.dev/gemma/terms): fine-tuned weights are "Model Derivatives"; when distributing you must pass on the use restrictions (Prohibited Use Policy) and provide the terms to recipients, among other notice obligations. Gemma 4 is released under Apache 2.0 (ai.google.dev/gemma/apache_2; Gemma 4 Hub repos list `apache-2.0`). Check which applies to your exact checkpoint.

**Qwen (Alibaba).** Varies by release *and size*: e.g. Qwen3-8B is `apache-2.0`, while Qwen2.5-72B-Instruct uses the custom "qwen" license and Qwen2.5-3B-Instruct the "qwen-research" license (Hub metadata). Read each repo's LICENSE.

**Mistral.** Varies by model: e.g. Mistral-7B-Instruct-v0.3 and Mistral-Small-3.2-24B-Instruct-2506 are `apache-2.0`; Mistral-Large-Instruct-2411 uses the Mistral Research License (MRL 0.1), which limits use of the models, derivatives and outputs to "Research Purposes" (personal, scientific or academic research, non-profit). Check each repo.

**Others:** many open-weight releases (e.g. OpenAI gpt-oss) are `apache-2.0`; some carry custom or non-commercial licenses (CC BY-NC variants). Apache-2.0 still requires keeping the license/NOTICE files and stating changes when you redistribute.

## Adapters are derivatives too

A LoRA adapter is trained from (and only works with) the base model; treat it as subject to the base license when you publish it. Put the base model id, its license, and any required attribution/naming in the adapter's model card. On the Hub, set `base_model:` and the right `license:` in the card metadata.

## Dataset licenses

- Check each dataset's card (`license:` field) and the original source's terms. CC BY requires attribution; CC BY-SA adds share-alike (how that applies to model weights is contested; get advice); CC BY-NC forbids commercial use.
- Scraped data, customer data, and support logs: check contracts, privacy policy, and data-protection law (consent, purpose limitation, deletion requests). Scrub PII (see `data-prep.md`).
- Synthetic data from a commercial API: many providers' terms restrict using outputs to develop competing models. Read the current terms of the provider you used.

## Ship checklist

- [ ] Base model license read for the exact repo/revision; commercial use allowed for your case.
- [ ] Naming/attribution obligations applied (e.g. Llama: "Llama" prefix in model name, "Built with Llama", license copy).
- [ ] Acceptable-use / prohibited-use policy passed on to users where required.
- [ ] Dataset licenses compatible; attribution recorded in the model card.
- [ ] Teacher-model output terms checked for synthetic data.
- [ ] LICENSE and NOTICE files shipped with weights/adapters.
