# LibreChat: troubleshooting

> Verified against LibreChat v0.8.8 / config v1.3.17 (docs: custom_endpoint, ai_endpoints/ollama, docker_override, local/docker), vLLM v0.31.0, llama.cpp server README, 2026-10-11

Order of work: (1) `scripts/check-endpoint.sh` from the host, (2) the same from inside the container network, (3) `docker logs LibreChat`, (4) the YAML.

```bash
docker logs LibreChat 2>&1 | tail -50
docker exec LibreChat sh -c 'wget -qO- --timeout=5 http://host.docker.internal:8000/v1/models | head -c 300'   # reachability from the api container (add a header if the server needs a key)
docker exec LibreChat sh -c 'ls -l /app/librechat.yaml'                                                           # is the file mounted?
```

| Symptom                                             | Likely cause and fix                                                                                                                                                                                                                                                                  |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Custom endpoint absent from the picker              | `librechat.yaml` not mounted at `/app/librechat.yaml`, schema error (read the startup log), `apiKey` missing or empty (the endpoint is dropped), wrong top-level indentation (`endpoints:` then `custom:` list), or `version:` too old for a field. Restart with `down` then `up -d`. |
| Picker shows it, model list empty                   | `fetch: true` failed. From the container, `GET <baseURL>/models` must work with the same key; check the allowlist on the key (LiteLLM virtual key `models`), and that `baseURL` ends with `/v1`. With `fetch: false` the list is exactly `models.default`.                            |
| Wrong or stale models                               | Config is cached (`cache: true`) and the model list loads at startup or first use; restart after gateway changes. Ollama: name must start with `ollama` for native `/api/tags`.                                                                                                       |
| `ECONNREFUSED` / fetch failed                       | `localhost` is the container. Use `host.docker.internal`, a Compose service name or the LAN address. Ollama and llama.cpp listening only on `127.0.0.1` are unreachable from containers. Prefer binding to the bridge gateway plus a firewall rule over `0.0.0.0`.                    |
| `401 Unauthorized`                                  | Key wrong, or the server checks a different header. vLLM `--api-key` honours only `Authorization: Bearer`, so with `provider: anthropic` (sends `x-api-key`) add `headers: { Authorization: 'Bearer ${...}' }`. `.env` changed but container not recreated: `docker compose up -d`.   |
| `404` on every call                                 | Missing `/v1` on an OpenAI endpoint, or `/v1` on a `provider: anthropic` root (becomes `/v1/v1/messages`). If the URL is already a complete completions URL, set `directEndpoint: true`.                                                                                              |
| `404` only on Messages                              | The server has no `/v1/messages`. Use the OpenAI path or put LiteLLM or llama-swap in front.                                                                                                                                                                                          |
| `422` / `400 unsupported parameter`                 | Server rejects a default field. Add `dropParams: ['stop', 'user', 'frequency_penalty', 'presence_penalty']` (what upstream recommends for Mistral) and retest; remove vendor params from `addParams`.                                                                                 |
| Replies cut off after a few words                   | The server defaults `max_tokens` very low and LibreChat does not send it. Add `addParams: { max_tokens: 4096 }` or set Max Tokens in the parameters panel.                                                                                                                            |
| Model never stops (Ollama llama3-style)             | Missing stop tokens: add stop sequences in the conversation parameters panel or `addParams.stop` for single-model endpoints.                                                                                                                                                          |
| Title generation errors or spawns a second model    | `titleModel` defaults to `gpt-3.5-turbo`. Set `titleModel: current_model` (or a real id), and `titleMessageRole: user` if the template rejects system. Turn titles off with `titleConvo: false`.                                                                                      |
| Agent never calls tools                             | Engine lacks tool-call parser/`--jinja`, or model does not support tools. Prove with `check-endpoint.sh`; see `references/agents-and-tools.md`.                                                                                                                                       |
| Thinking text in answers or errors after tool turns | Configure the engine's reasoning parser, or `customParams` (`reasoningKey`, `includeReasoningContent`).                                                                                                                                                                               |
| `claude` in a model name changes upload behaviour   | Document rules for `claude` ids apply on OpenAI custom endpoints; rename the alias.                                                                                                                                                                                                   |
| Stream stalls on first message                      | Model is loading (llama-swap, Ollama). Raise timeouts on every proxy hop; keep the model warm.                                                                                                                                                                                        |
| Login loops or CORS errors behind a proxy           | `DOMAIN_CLIENT` and `DOMAIN_SERVER` must match the public URL; set `TRUST_PROXY`.                                                                                                                                                                                                     |
| MongoDB crash loop on Apple Silicon                 | Needs AVX; use `mongo:4.4.18` in the override.                                                                                                                                                                                                                                        |
| Costs and context meter wrong                       | Declare `tokenConfig` for each model id; `/v1/models` has no such data.                                                                                                                                                                                                               |
| Users see each other's endpoints or secrets         | `user_provided` keys are per user; shared keys in `.env` are server-side only. Use `tenantId` for tenant-scoped endpoints, upgrading every replica first.                                                                                                                             |

If the server answers curl but LibreChat cannot, turn on request logging at the server (vLLM `--uvicorn-log-level debug`, LiteLLM `--detailed_debug`, llama-server verbose) and compare the path and `model` field LibreChat sends.
