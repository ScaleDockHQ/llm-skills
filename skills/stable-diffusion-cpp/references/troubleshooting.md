# stable-diffusion.cpp: troubleshooting

> Verified against stable-diffusion.cpp master-956-1b0ba10 (docs/troubleshooting.md, docs/performance.md, examples/server), 2026-10-11

Evidence first: rerun with `-v` (`--log-level verbose`; `debug` for buffer sizes) and `sd-server --list-devices`.

| Symptom                                                    | Likely cause and fix                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Completely black or white images or videos, NaN in the log | numeric overflow on some backend, device, model or weight format. Restart with `--linear-scale 0.0078125 --attn-scale 0.0078125`; if it persists try `0.00390625`. `--attn-scale` only takes effect with `--fa` or `--diffusion-fa`. Same seed and prompt to compare. Upstream wants a bug report with command, backend, hardware, model, format, logs and the scale values tried. |
| A video model generates nothing or errors in `sd-cli`      | add `--mode vid_gen`; `--video-frames` alone does not select video mode, and video models need it even for one frame.                                                                                                                                                                                                                                                              |
| Load fails or output is garbage                            | wrong text encoder, VAE or diffusion file for the architecture; use the model's page under upstream `docs/`. With `SD_USE_UPSTREAM_GGML=ON` builds, INT8 files and FP8 GGUF files are rejected (build.md); use the default patched GGML for them.                                                                                                                                  |
| Out of memory                                              | `performance-memory.md` in order: `--diffusion-fa`, `--vae-tiling`, smaller quant, `--offload-to-cpu`, `--params-backend disk`, `--max-vram`.                                                                                                                                                                                                                                      |
| GPU not used, slow                                         | the binary lacks that backend (`sd-server --list-devices`); on Linux there is no CUDA zip, use the `-cuda` image or build with `-DSD_CUDA=ON`.                                                                                                                                                                                                                                     |
| First request very slow on macOS                           | Metal kernels are compiled at start (about 15 s for the flash-attention library on an arm64 Mac in our test); wait for it, and judge speed on the second request.                                                                                                                                                                                                                  |
| `<lora:...>` has no effect on the server                   | prompt tags are unsupported on every server API; send the structured `lora` array and set `--lora-model-dir` (`serve-and-api.md`).                                                                                                                                                                                                                                                 |
| LoRA looks wrong on a quantized model                      | `--lora-apply-mode at_runtime` (auto already picks it for quantized weights) or use unquantized weights.                                                                                                                                                                                                                                                                           |
| HTTP 429 from `/sdcpp/v1/img_gen`                          | job queue full; wait or cancel with `POST /sdcpp/v1/jobs/{id}/cancel`.                                                                                                                                                                                                                                                                                                             |
| HTTP 400 from native API                                   | empty or invalid JSON, unsupported mode for the loaded model (check `supported_modes`), or bad parameters.                                                                                                                                                                                                                                                                         |
| `sd_cpp_extra_args` ignored                                | it only works inside `prompt` on `/v1` and `/sdapi/v1`; native `/sdcpp/v1` takes the schema directly.                                                                                                                                                                                                                                                                              |
| Cloudflare 524                                             | synchronous generation exceeded 125 s; shorter job, async API or private path (`combos/llama-swap-litellm.md`).                                                                                                                                                                                                                                                                    |
| Port in use or unreachable                                 | default is `127.0.0.1:1234`; check `ss -ltnp \| grep 1234`; inside a container bind `0.0.0.0` and publish the port.                                                                                                                                                                                                                                                                |
| Option from an old guide rejected                          | flags are renamed often (`--clip-on-cpu`, `--vae-on-cpu` deprecated; `--qwen2vl` is an alias of `--llm`); compare with `sd-server --help`.                                                                                                                                                                                                                                         |
