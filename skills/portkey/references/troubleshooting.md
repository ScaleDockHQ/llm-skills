# Portkey troubleshooting

> Verified against Portkey AI Gateway v1.15.2 (src/middlewares/requestValidator, src/globals.ts, handlers) and docs.portkey.ai (configs, fallbacks, retries), 2026-10-11

| Symptom                                                                                                                  | Likely cause                                                                             | Fix                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Invalid custom host` or 400 on `x-portkey-custom-host`                                                                  | SSRF guard blocks private IPs, internal TLDs, metadata addresses, credentials in the URL | Set `TRUSTED_CUSTOM_HOSTS` to the exact host or IP (and `localhost` if still needed); inside Docker use `host.docker.internal` or a service name |
| Config rejected, `Invalid configuration. It must have either 'provider' and 'api_key', or 'strategy' and 'targets', ...` | Config lacks a required combination                                                      | Add `provider` plus `api_key`, or `strategy` plus `targets`                                                                                      |
| `Invalid 'mode' value`                                                                                                   | Typo or unsupported mode                                                                 | Use `single`, `fallback`, `loadbalance` or `conditional`                                                                                         |
| Invalid `provider`                                                                                                       | Slug not in the gateway's list                                                           | Use the provider slug from the docs (for example `openai`, `anthropic`, `azure-openai`, `vertex-ai`, `ollama`); `@slug` forms are hosted only    |
| 401 from provider                                                                                                        | Key missing: gateway forwards `Authorization` as the provider key                        | Send the provider key, or `api_key` in the target; do not send the Portkey key to the OSS gateway                                                |
| `@openai-prod/gpt-4o` not found                                                                                          | Model Catalog is hosted-only                                                             | Use `provider` plus `api_key` or hosted base URL with `x-portkey-api-key`                                                                        |
| Fallback never happens                                                                                                   | `on_status_codes` excludes the failing code, error returned as 200, or timeouts          | Widen `on_status_codes`; add `408` for timeouts; test with a forced failure                                                                      |
| Retries make latency huge                                                                                                | Attempts times targets times timeout                                                     | Lower attempts; set `request_timeout`; one retry owner across layers                                                                             |
| Cache never hits                                                                                                         | Cache not enabled at build, params differ, metadata differs, hosted-only mode            | Check `x-portkey-cache-status`; semantic cache is not in open source                                                                             |
| Console shows "Admin token is required"                                                                                  | Built from `main` without `admin_token`                                                  | Set `admin_token` in `conf.json` before building, or run `--headless`, or use a release image                                                    |
| Console missing                                                                                                          | `NODE_ENV=production` or `--headless`                                                    | Unset production mode for local debugging only                                                                                                   |
| Port 8787 reachable from the network                                                                                     | Compose maps `8787:8787`; no inbound auth                                                | Map `127.0.0.1:8787:8787`; add an authenticating proxy before exposing                                                                           |
| Streaming cut off behind a proxy                                                                                         | Proxy buffering or short timeout                                                         | Disable response buffering and raise idle timeouts in the proxy                                                                                  |
| Behavior differs from docs                                                                                               | Docs describe hosted features                                                            | Check the source or release notes for your tag; see `serve-config.md`                                                                            |
