# GPT-QModel: troubleshooting

> Verified against GPT-QModel v7.5.0 and main, 2026-10-11

| Symptom                                               | Likely cause                                                                                        | Fix                                                                                                                                                                       |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Install resolves other torch/transformers versions    | Requires `torch>=2.8.0`, `transformers>=5.14.0`                                                     | Use a dedicated venv; install the matching CUDA torch first                                                                                                               |
| First import or load takes minutes                    | JIT kernel compilation (`ninja`)                                                                    | Wait once; keep `~/.cache/gptqmodel`; prewarm Machete; `GPTQMODEL_OFFLINE=1` needs the CUTLASS checkout                                                                   |
| Build error about Python headers                      | Missing `python3-dev`, compiler or CUDA toolkit                                                     | Install them; or use a prebuilt wheel path if provided for your platform                                                                                                  |
| Another process is building the kernel and loads hang | Cross-process build lock                                                                            | Wait up to `GPTQMODEL_TORCH_OPS_LOCK_TIMEOUT` (default 600 s or 5x baseline) or give each process its own `GPTQMODEL_TORCH_EXTENSIONS_DIR`                                |
| `model_type` not supported                            | Not in `MODEL_MAP`                                                                                  | Check the README table; upgrade or use `main`; otherwise wait for support                                                                                                 |
| `act_group_aware == True requires desc_act == False`  | Both set                                                                                            | Choose one                                                                                                                                                                |
| `damp_percent must between 0 and 1`                   | Bad value                                                                                           | Use 0.01 to 0.1 range as in defaults (0.05)                                                                                                                               |
| Cholesky or Hessian failures in a layer               | Poorly conditioned Hessian                                                                          | Raise `damp_percent`, check calibration data length and variety                                                                                                           |
| CUDA OOM during quantization                          | Large layers, big batch, data-parallel clones                                                       | Lower `batch_size`; `auto_forward_data_parallel=False`; keep `offload_to_disk=True`; `wait_for_submodule_finalizers=True`; use `moe_vram_strategy="balanced"` across GPUs |
| Host RAM exhausted                                    | Offload disabled or large model                                                                     | `offload_to_disk=True` with a fast `offload_to_disk_path`                                                                                                                 |
| Experts get no calibration (MoE accuracy drop)        | Biased routing                                                                                      | Test `FailSafe`, `ExpertsRoutingOverride`, `ExpertsRoutingBypass`                                                                                                         |
| Output worse than expected                            | Tiny or off-domain calibration, 2-3 bits, no reordering                                             | Better calibration set, larger `bits`, smaller `group_size`, `act_group_aware`, EoRA                                                                                      |
| `GPTQMODEL_RESUME is retired`                         | Old env-var based resume                                                                            | Use `checkpoint=CheckpointConfig(path=...)` in a new directory                                                                                                            |
| `CheckpointStopped` raised                            | Safe stop requested (Ctrl+C or SIGTERM)                                                             | Rerun the same script with the same inputs; do not call `save()` in the handler                                                                                           |
| Resume refuses                                        | Source, calibration, config, versions or device topology changed                                    | Restore the originals or start a fresh checkpoint directory                                                                                                               |
| Checkpoint unsupported error                          | Model type not Llama or Qwen3 MoE, `offload_to_disk=False`, dynamic/rotation/embedding quantization | Run without checkpointing or change the config                                                                                                                            |
| Quantized model fails in Transformers                 | `dynamic` overrides used                                                                            | Avoid `dynamic`, or serve with GPT-QModel                                                                                                                                 |
| SGLang rejects the checkpoint                         | Format not GPTQ (`gptq`, `gptq_v2`, `marlin`) or AWQ (`gemm`, `marlin`)                             | Re-save in an accepted format                                                                                                                                             |
| Backend error at load                                 | Kernel not valid for format or hardware                                                             | `backend=BACKEND.AUTO`; check `models-and-hardware.md`                                                                                                                    |
| Slight output drift between runs                      | fp32 accumulation toggles                                                                           | Keep `GPTQMODEL_FP32_ACCUM=1` for evaluation                                                                                                                              |
| Triton cache crashes with free-threaded Python        | Triton cache not thread-safe                                                                        | `TritonPatch.apply()` first in the script                                                                                                                                 |
| `serve()` unreachable or exposed                      | Default host `0.0.0.0`, port 80                                                                     | Pass `host="127.0.0.1"` and a high port                                                                                                                                   |

If nothing matches, upgrade to the latest release (and `main` for new models), then search https://github.com/ModelCloud/GPTQModel/issues with the exact error text.
