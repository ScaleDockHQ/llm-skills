# SGLang: troubleshooting

> Verified against SGLang v0.5.21 (docs: references/faq, get-started/quickstart "Common Troubleshooting", advanced_features/{hyperparameter_tuning,server_arguments,pd_disaggregation}; repo-carried pitfalls from earlier DGX Spark runs are marked "carried over"), 2026-10-11

Collect first (read-only, no secrets):

```bash
docker logs --tail 300 sglang 2>&1 | tail -100            # or journalctl -u sglang -n 200 --no-pager
curl -fsS http://127.0.0.1:30000/health -o /dev/null -w '%{http_code}\n'
nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu --format=csv
curl -fsS http://127.0.0.1:30000/server_info | jq -r .version
sglang version
```

## Symptom table

| Symptom                                                                                   | Likely cause                                                                                  | Fix                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `CUDA out of memory` at startup                                                           | `--mem-fraction-static` too high, other process on the GPU, CUDA graph capture, large context | Lower `--mem-fraction-static` (0.8 -> 0.7), `--cuda-graph-max-bs-decode`, `--context-length`; check `nvidia-smi` for other users                                                                             |
| OOM during prefill of long prompts                                                        | prefill activation spike                                                                      | `--chunked-prefill-size 4096` or `2048`                                                                                                                                                                      |
| OOM during decode under load                                                              | too many concurrent requests                                                                  | `--max-running-requests` down; `--mem-fraction-static` down                                                                                                                                                  |
| OOM when requesting `logprobs` on long prompts                                            | input logprobs are large                                                                      | Set `logprob_start_len`; lower `--mem-fraction-static`                                                                                                                                                       |
| `CUDA error: an illegal memory access was encountered`                                    | kernel bug, or OOM reported as this error                                                     | Treat as OOM first (above); then try another attention backend; file an issue with `--crash-dump-folder` output                                                                                              |
| Hangs at init / "avail mem" tiny                                                          | out of memory, NCCL problems, bug                                                             | Lower `--mem-fraction-static`, `--cuda-graph-max-bs-decode`, `--chunked-prefill-size`; check NCCL (below)                                                                                                    |
| Never becomes healthy; GPU memory used but `/health` fails                                | still loading weights / capturing CUDA graphs / autotuning FlashInfer                         | Wait; watch logs; first start is slow (minutes); give probes a long startup window                                                                                                                           |
| `KV cache pool is full. Retract requests.` often                                          | `--schedule-conservativeness` too low or too much concurrency                                 | Raise it (1.3); lower `--max-running-requests`; more KV (`--mem-fraction-static` up, FP8 KV)                                                                                                                 |
| Low throughput, `token usage` < 0.9 with queue                                            | too conservative                                                                              | `--schedule-conservativeness 0.3`                                                                                                                                                                            |
| `OSError: CUDA_HOME environment variable is not set`                                      | pip install without CUDA toolkit on `PATH`                                                    | `export CUDA_HOME=/usr/local/cuda-<ver>`, or install FlashInfer first                                                                                                                                        |
| FlashInfer errors on sm75+                                                                | kernel/JIT issue                                                                              | `--attention-backend triton --sampling-backend pytorch`; reinstall FlashInfer: `pip3 install --upgrade flashinfer-python --force-reinstall --no-deps && rm -rf ~/.cache/flashinfer`                          |
| `ptxas` error on B300/GB300 (sm_103a)                                                     | wrong bundled ptxas                                                                           | `export TRITON_PTXAS_PATH=/usr/local/cuda/bin/ptxas` (upstream quickstart)                                                                                                                                   |
| pip installs SGLang 0.5.9                                                                 | uv < 0.12.0 without pre-releases                                                              | `uv pip install --prerelease=allow sglang` (or upgrade uv)                                                                                                                                                   |
| Image pull works but CUDA init fails / `unsupported driver`                               | CUDA 13 image on an old driver (CUDA 12 lane ended at v0.5.19)                                | Update the driver, or pin `v0.5.19-cu129` consciously                                                                                                                                                        |
| `peer access is not supported between these two devices`                                  | no P2P between GPUs                                                                           | Add `--enable-p2p-check`                                                                                                                                                                                     |
| Multi-GPU container: shared-memory errors (for example a `Bus error`, unverified wording) | too small `/dev/shm`                                                                          | `--ipc=host` or `--shm-size 32g`; in Kubernetes mount an `emptyDir` with `medium: Memory` at `/dev/shm`                                                                                                      |
| Multi-node deadlock at startup                                                            | NCCL on the wrong interface, firewall, version mismatch, CUDA graph capture                   | Same image on all nodes; `NCCL_SOCKET_IFNAME`; open `--dist-init-addr` port between nodes; `NCCL_DEBUG=INFO`; try `--disable-decode-cuda-graph --disable-prefill-cuda-graph` (older: `--disable-cuda-graph`) |
| Multi-node: API answers on every interface                                                | `--network host` with `--host 0.0.0.0`                                                        | Bind `127.0.0.1` or set `--api-key`/firewall (carried over)                                                                                                                                                  |
| Tool calls come back as plain text                                                        | no `--tool-call-parser`, wrong parser, or template without tools                              | Set the right parser for the model; check `--chat-template`/`--hf-chat-template-name tool_use`                                                                                                               |
| `content` empty with gpt-oss tool calls                                                   | parser drops analysis-channel text                                                            | Expected per the tool-parser doc; read `reasoning_content`/tool calls; see `features.md`                                                                                                                     |
| Reasoning text missing from the answer                                                    | parser strips it into `reasoning_content`                                                     | Request `separate_reasoning: true` and read that field; or drop `--reasoning-parser`                                                                                                                         |
| Structured output stalls or is slow                                                       | grammar compilation, outlines disk cache                                                      | Use `xgrammar`; `--disable-outlines-disk-cache`; watch `sglang:grammar_compilation_time_seconds`                                                                                                             |
| NVFP4 checkpoint refuses to load or is garbage                                            | missing/incorrect quantization flag                                                           | `--quantization modelopt_fp4` (carried over from DGX Spark playbook); do not add `--quantization` on top of other pre-quantized formats                                                                      |
| Different outputs at `temperature 0`                                                      | dynamic batching and prefix caching                                                           | `--enable-deterministic-inference`, or `--disable-radix-cache` with single requests                                                                                                                          |
| Cache hit rate near 0 on agent workloads                                                  | prompt prefix changes each turn (timestamps, attribution header)                              | Keep prefix stable; for Claude Code set `CLAUDE_CODE_ATTRIBUTION_HEADER=0`; `--enable-cache-report` to see `cached_tokens`                                                                                   |
| `Address already in use` on 30000                                                         | previous container/process                                                                    | `ss -ltnp` and look for port 30000; stop the old one; `killall_sglang` only if it is yours                                                                                                                   |
| Orphan GPU memory after a crash                                                           | leftover scheduler processes                                                                  | `pkill -f sglang.launch_server` after confirming PIDs with `pgrep -af sglang`; or `docker rm -f` the container                                                                                               |
| Slow first request after start                                                            | CUDA graph or JIT warm-up                                                                     | Warm with one request in a deploy script; persist `SGLANG_CACHE_DIR` and `~/.cache/flashinfer`                                                                                                               |
| Watchdog crash `watchdog timeout`                                                         | a forward took over `--watchdog-timeout` (300s)                                               | Look for OOM/NCCL stalls; raise only for known long prefill; capture `--crash-dump-folder`                                                                                                                   |
| Wrong model name from `/v1/models`                                                        | `--served-model-name` unset                                                                   | Set it to the gateway's expected name                                                                                                                                                                        |
| Anthropic client gets raw tool text                                                       | no `--tool-call-parser`                                                                       | Add the parser; restart                                                                                                                                                                                      |
| `/health_generate` slow or loading the server                                             | it generates a token each call                                                                | Use `/health` for probes (carried over)                                                                                                                                                                      |
| `spark` Docker tag runs an old SGLang                                                     | stale tag (last push 2025-11-06)                                                              | Use `v0.5.21-cu130`; verify with `/server_info` `.version` (carried over)                                                                                                                                    |

## NCCL and network diagnostics

```bash
export NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=INIT,NET      # in the launch environment
python3 -c 'import torch; print(torch.cuda.nccl.version())'
ip -br addr; ss -ltn | grep -E ':(30000|50000)\b'      # init port reachable from the other node?
```

Check from the other node: `nc -zv <rank0-ip> <init-port>`. Match `NCCL_SOCKET_IFNAME` to the high-speed interface. For RoCE set `NCCL_IB_GID_INDEX`. In PD mode also verify the bootstrap port (default 8998) and `--disaggregation-ib-device`.

## When it is a bug

Reproduce with the smallest command, note version (`sglang version`), image digest, GPU/driver, full launch args (redact keys), and logs; check issues at `https://github.com/sgl-project/sglang/issues`. Try the newest release and, if needed, `dev` image once to see if it is fixed (do not leave production on it).

## Not covered here
