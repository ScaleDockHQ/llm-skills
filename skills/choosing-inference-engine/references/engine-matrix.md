# Choosing an Inference Engine: engine matrix

> Verified against vLLM v0.31.0 (docs: installation, quantization, features), SGLang v0.5.21 (README, docs index), TensorRT-LLM v1.2.1 (README, support matrix, feature combination matrix), llama.cpp v0.6.0 (README, server README), Ollama v0.40.3 (docs: gpu, import, faq), TensorFold v1.0.7 (README), ExLlamaV3 v1.6.1 (README), 2026-10-11

Legend: **yes** = stated in the upstream page named in Sources. **no** = upstream says it is unsupported, or the hardware is absent from a list that is documented as complete. **not listed** = the upstream page does not mention it, which is not proof it fails. **(unverified)** = not checked against upstream in this pass.

Notes:

1. vLLM's own quantization hardware table stops at Hopper (SM 9.0). It does not list Blackwell, so confirm the exact Blackwell kernel path (FP8, NVFP4, MXFP4) in the release notes for the version you install. The vLLM README names NVFP4 and TRTLLM-GEN kernels. Whether a given GB10 or RTX 50 combination works at your version is **(unverified)**.
2. ExLlamaV3's README requires PyTorch with CUDA 12.4 or later and does not list GPU generations. Blackwell consumer and GB10 support depends on the torch and CUDA build. Check the TabbyAPI image tag and the ExLlamaV3 issues before buying hardware for it.
3. TensorRT-LLM's support-matrix page lists Blackwell, Grace Hopper, Hopper, Ada and Ampere on Linux x86_64 or aarch64. That page still shows container 25.06 and TensorRT 10.11 while the latest release is v1.2.1, so treat its software rows as stale and read the release notes for your version.
4. Ollama minimum for NVIDIA: compute capability 5.0 and driver 550 or newer (570 or newer for compute 5.0 to 6.2).
5. TensorFold 1.0.7 admits only the listed model and platform combinations. Everything else is "not qualified", not "slow".

**Quality gate.** Every quantized weight format and every KV-cache quantization above changes numerics. Gate each with the `llm-evals` skill before serving traffic: `npx skills add ScaleDockHQ/llms-skills --skill llm-evals`. Ollama's own FAQ says `q4_0` KV cache can hurt more at high context and for high-GQA models.

Feature interactions matter. TensorRT-LLM publishes a combination matrix: speculative decoding (linear, dynamic trees, legacy n-gram) is marked **No** with pipeline parallelism, and logits post-processing is **No** with disaggregated serving and speculative decoding. vLLM's feature matrix marks speculative decoding **No** with LoRA. Read the engine's matrix before stacking features.

## 4. Operational character

| Engine       | Best at                                                          | Watch for                                                                |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| vLLM         | Broad hardware, many models, high-concurrency serving            | Startup time, memory headroom, version-specific kernel paths on new GPUs |
| SGLang       | Agentic and prefix-heavy workloads, large-scale serving          | Fast release cadence (pre-release flag in the install command)           |
| TensorRT-LLM | Peak NVIDIA throughput on Hopper and Blackwell                   | NVIDIA-only, narrower model list, support page lags releases             |
| llama.cpp    | Widest hardware, GGUF, CPU+GPU hybrid, small footprint           | Fewer batching and parallelism features than the GPU-first engines       |
| Ollama       | Easiest local setup, model library, lifecycle (load, unload)     | Defaults favour one user; tune parallelism and context deliberately      |
| TensorFold   | Exact decoding, no Python in the serving path, qualified recipes | Only qualified model and platform pairs; check the table first           |
| ExLlamaV3    | Fitting big models in small VRAM with EXL3 and cache quant       | A library; TabbyAPI is the server and calls itself a hobby project       |
