# AnythingLLM: troubleshooting

> Verified against AnythingLLM v1.17.0 (docs: installation-docker/local-docker, installation-docker/localhost, ollama-connection-troubleshooting, agent-not-using-tools; source providers), vLLM v0.31.0, llama.cpp server README, 2026-10-11

Order of work: (1) `scripts/check-endpoint.sh` from the host, (2) the same URL from inside the container, (3) `docker logs anythingllm`.

```bash
docker logs anythingllm 2>&1 | tail -50
docker exec anythingllm sh -c 'curl -sS -m 5 -o /dev/null -w "%{http_code}\n" http://host.docker.internal:8000/v1/models'   # status only; add -H "Authorization: Bearer ..." from a 0600 file if the server needs it
```

| Symptom                                                               | Likely cause and fix                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fetch failed`, connection refused, no models from Ollama or a server | `localhost`, `127.0.0.1`, `0.0.0.0` are the container. Use `host.docker.internal` (macOS, Windows) or `172.17.0.1` (Linux default bridge) with the server's port. The server must listen beyond loopback; do not bind unauthenticated Ollama or llama.cpp to every interface, firewall the port instead. |
| Generic OpenAI: `404` on every request                                | Base URL missing `/v1`, or doubled. Generic OpenAI wants `.../v1`; `curl <base>/models` must work.                                                                                                                                                                                                       |
| `404 model not found`                                                 | `GENERIC_OPEN_AI_MODEL_PREF` is typed, not discovered; copy the id from `GET /v1/models`, and check gateway aliases. Workspace override may point at an old name.                                                                                                                                        |
| `401 Unauthorized`                                                    | Wrong key, server expects another header: use `GENERIC_OPEN_AI_CUSTOM_HEADERS` for `X-Api-Key` style auth. `.env` edited but container not restarted.                                                                                                                                                    |
| Settings revert or vanish after restart                               | `.env` not mounted at `/app/server/.env`, or storage not mounted. Re-run with both `-v` mounts.                                                                                                                                                                                                          |
| `unable to open database file`                                        | Storage owned by root; `sudo chown -R 1000:1000 "$STORAGE_LOCATION"`. Not `chmod 777`.                                                                                                                                                                                                                   |
| `Illegal instruction (core dumped)`                                   | CPU lacks AVX2 (LanceDB). Expose host CPU type to the VM or use another vector DB.                                                                                                                                                                                                                       |
| History or documents silently cut, replies ignore context             | Token limit still 4096. Set `*_MODEL_TOKEN_LIMIT` or the UI Token context window to the real window.                                                                                                                                                                                                     |
| Replies end after a few words                                         | Server default for `max_tokens` is tiny: set Max Tokens (`GENERIC_OPEN_AI_MAX_TOKENS`), or `GENERIC_OPEN_AI_MODEL_MAX_TOKEN_KEY='max_completion_tokens'` if the server wants that field.                                                                                                                 |
| 400 on streaming with `stream_options`                                | Leave `GENERIC_OPEN_AI_REPORT_USAGE` unset (default).                                                                                                                                                                                                                                                    |
| Stream garbled or hangs                                               | Try `GENERIC_OPENAI_STREAMING_DISABLED='true'`; check proxy buffering and idle timeouts in front.                                                                                                                                                                                                        |
| First message very slow (swapping engines)                            | llama-swap or Ollama is loading the model; raise `OLLAMA_RESPONSE_TIMEOUT` for Ollama and proxy timeouts elsewhere. Keep one model per workspace.                                                                                                                                                        |
| `@agent` replies but never uses tools                                 | See `references/agents-and-mcp.md`: model or parser issue, tools overloaded, 4096 context. Try `PROVIDER_DISABLE_NATIVE_TOOL_CALLING` or fix the engine's parser.                                                                                                                                        |
| Anthropic provider cannot use my gateway                              | It has no base-URL setting; use Generic OpenAI or the LiteLLM provider against an OpenAI route.                                                                                                                                                                                                          |
| Ollama models list empty in a container                               | URL not detected: type `http://host.docker.internal:11434` (or the LAN address). `ollama run` alone does not start the API; run `ollama serve`.                                                                                                                                                          |
| Embedding fails with `fetch failed`                                   | Embedder is configured separately from the LLM; fix the embedder URL the same way.                                                                                                                                                                                                                       |
| MCP server not listed                                                 | Open Agent Skills (that starts servers), then Refresh; check `plugins/anythingllm_mcp_servers.json` in storage and container resources.                                                                                                                                                                  |

If curl works from the host but not from inside the container, it is networking, not AnythingLLM.
