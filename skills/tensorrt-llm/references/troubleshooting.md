# Troubleshooting

> Verified against TensorRT-LLM v1.2.1 docs, `main` installation guide, NVIDIA DGX Spark playbook (troubleshooting tables), Dynamo v1.5.1 TensorRT-LLM known issues, 2026-10-11

Start with logs: `docker logs --tail 200 <container>`. Always capture `trtllm-serve --version`-equivalent (`curl :8000/version`), image tag, GPU model and driver (`nvidia-smi`).

| Symptom                                                                                                                 | Cause                                                                           | Fix                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Bus error (core dumped)` in a container                                                                                | Shared memory too small                                                         | Run with `--ipc=host` (or large `--shm-size`) plus `--ulimit memlock=-1 --ulimit stack=67108864`.                                                                                                             |
| CUDA out of memory at start                                                                                             | KV fraction, batch or graphs too big; shared memory on Spark                    | Lower `kv_cache_config.free_gpu_memory_fraction` (upstream: 0.7 or lower), `--max_batch_size`, `--max_num_tokens`; stop other engines; smaller `cuda_graph_config.max_batch_size` (each graph up to ~200 MB). |
| OOM while loading weights (e.g. Nemotron Super 49B on Spark)                                                            | Parallel weight loading memory spike                                            | `export TRT_LLM_DISABLE_LOAD_WEIGHTS_IN_PARALLEL=1`.                                                                                                                                                          |
| OOM on DGX Spark though the model should fit                                                                            | Page cache holds unified memory                                                 | `sudo sh -c 'sync; echo 3 > /proc/sys/vm/drop_caches'` (ask first); lower the KV fraction to 0.8.                                                                                                             |
| `ptxas fatal` while serving                                                                                             | Triton kernel compile needs ptxas                                               | `TRITON_PTXAS_PATH=/usr/local/cuda/bin/ptxas` (and `CPATH=/usr/local/cuda/include`); with `mpirun` add `-x TRITON_PTXAS_PATH`.                                                                                |
| gpt-oss fails or tries to download tiktoken files at start                                                              | Missing encodings                                                               | Pre-fetch `o200k_base.tiktoken` and `cl100k_base.tiktoken`, mount, set `TIKTOKEN_ENCODINGS_BASE`.                                                                                                             |
| Cannot access gated repo / "Permission denied" on download                                                              | Missing or invalid `HF_TOKEN`, license not accepted                             | Accept the license on the model page, export a valid token (never print it), `HF_HUB_OFFLINE=0` for the first fetch.                                                                                          |
| `Model not found` from clients                                                                                          | `model` differs from the served id                                              | `curl :8000/v1/models`; send that id (v1.2.1 has no `--served_model_name`), or use a gateway alias.                                                                                                           |
| `error: no such option` for a flag from a doc                                                                           | Flag exists on another tag (`--set`, `--served_model_name`, `--hf_revision`)    | `trtllm-serve serve --help` in your image; see `serve-config.md`.                                                                                                                                             |
| Old command with `--backend pytorch`                                                                                    | `--backend` is marked deprecated on main                                        | Drop it. On v1.2.1 `--backend tensorrt` selects legacy engines.                                                                                                                                               |
| YAML key rejected                                                                                                       | Renamed or removed field (`pytorch_backend_config` examples)                    | Use top-level keys from the LLM API reference for your tag.                                                                                                                                                   |
| Server starts but `/v1/responses` fails                                                                                 | Older image or gateway mismatch                                                 | Use chat completions via the gateway, or update the image.                                                                                                                                                    |
| Reasoning text appears in `content`, or tool calls not parsed                                                           | No or wrong parser                                                              | Set `--reasoning_parser` and `--tool_parser` for the model family (`features.md`).                                                                                                                            |
| Constrained output (JSON schema) ignored                                                                                | `guided_decoding_backend` unset                                                 | Set `guided_decoding_backend: xgrammar` in YAML.                                                                                                                                                              |
| Multimodal request errors with KV reuse                                                                                 | Multimodal not compatible with reuse                                            | `kv_cache_config.enable_block_reuse: false`; use Chat API only.                                                                                                                                               |
| `The application appears to have been direct launched using "srun", but OMPI was not built with SLURM support`          | MPI without Slurm support (pip installs)                                        | Rebuild or reconfigure MPI with Slurm/PMIx support; use `--mpi=pmix` as in upstream's example; or use the release container.                                                                                  |
| `mpi4py.MPI.Exception: MPI_ERR_UNKNOWN: unknown error` at startup (long hostnames, pods)                                | Open MPI 5 rejects long hostnames in `MPI_Comm_spawn`                           | `export PMIX_HOSTNAME=trtllm-node` (any short string) before starting.                                                                                                                                        |
| `mpirun` hangs on two nodes                                                                                             | Missing hostfile, SSH keys or IB device in one container; interface names wrong | Check both containers: hostfile at `/etc/openmpi-hostfile`, `~/.ssh` mounted, `/dev/infiniband`, correct `UCX_NET_DEVICES` / `NCCL_SOCKET_IFNAME`.                                                            |
| `UCX WARN network device 'enp1s0f0np0' is not available`                                                                | Only one CX7 port used                                                          | Ignore if inference works.                                                                                                                                                                                    |
| MPI hostname test returns a single hostname (two Sparks)                                                                | Nodes not reachable on the hostfile IPs                                         | Verify IPs and routes between the two nodes.                                                                                                                                                                  |
| Two-node container exits immediately                                                                                    | Entrypoint script failed or port 2233 already in use                            | `docker logs`, make sure no other container uses port 2233, and the script download succeeded.                                                                                                                |
| pip install replaced CUDA 13 torch with a CUDA 12 build                                                                 | pip resolver                                                                    | Constrain torch (`install.md`).                                                                                                                                                                               |
| `RuntimeError: The NVIDIA driver on your system is too old` (from PyTorch)                                              | Image CUDA newer than host driver                                               | Upgrade the driver to the tag's minimum (Dynamo lists 580+ for CUDA 13.1 images) or use an older tag.                                                                                                         |
| Container hangs before ready with `--network host` (Dynamo notes, seen on Amazon Linux 2023)                            | Cause unestablished (mpi4py discussion)                                         | Use bridge networking with published ports where possible; tracked upstream.                                                                                                                                  |
| Disaggregated workers hang after sustained load; log `num_fitting_reqs=0 and fitting_disagg_gen_init_requests is empty` | `max_tokens_in_buffer` smaller than max ISL                                     | Set `cache_transceiver_config.max_tokens_in_buffer` above your max input length; restart workers.                                                                                                             |
| `NIXL ... LIBFABRIC` backend not used                                                                                   | Container lacks the NIXL LIBFABRIC plugin                                       | Rebuild NIXL with libfabric or point `NIXL_PLUGINS_DIR` at a compatible `libplugin_LIBFABRIC.so`.                                                                                                             |
| KV transfer hangs across NVLink domains                                                                                 | UCX picks MNNVL across domains                                                  | `UCX_CUDA_IPC_ENABLE_MNNVL=n`, check `UCX_NET_DEVICES`, `UCX_RNDV_SCHEME` on GB200.                                                                                                                           |
| `n > 1` requests rejected                                                                                               | Default deterministic decoding path                                             | Set `TLLM_ALLOW_N_GREEDY_DECODING=1` on that worker (per Dynamo docs).                                                                                                                                        |
| Slow first requests, then fine                                                                                          | CUDA graph capture, lazy connections                                            | Warm up before measuring; not a bug.                                                                                                                                                                          |
| Speculative decoding slower or errors                                                                                   | Large batch, tokenizer mismatch, overlap scheduler on                           | Use it at low batch sizes, same tokenizer for draft and target, `disable_overlap_scheduler: true` for two-model.                                                                                              |
| `Import tensorrt_llm fails` in container                                                                                | Container runtime issue                                                         | Restart the Docker daemon and retry (playbook).                                                                                                                                                               |
| `Error response from daemon: error while validating Root CA Certificate`                                                | Clock out of sync                                                               | `sudo timedatectl set-ntp true` (playbook).                                                                                                                                                                   |

## Checks that avoid guessing

```bash
nvidia-smi --query-gpu=name,compute_cap,memory.used,memory.total --format=csv
docker exec <c> python3 -c "import tensorrt_llm,torch;print(tensorrt_llm.__version__,torch.version.cuda)"
docker exec <c> printenv TRT_LLM_GIT_COMMIT
docker logs <c> 2>&1 | grep -i -e error -e warn -e "kv cache" | tail -30
curl -s http://127.0.0.1:8000/health -o /dev/null -w '%{http_code}\n'
```

## When to escalate

Search issues at https://github.com/NVIDIA/TensorRT-LLM/issues with the exact error string, then file one with image tag, `TRT_LLM_GIT_COMMIT`, GPU, driver, the YAML and the full startup log (redact tokens).
