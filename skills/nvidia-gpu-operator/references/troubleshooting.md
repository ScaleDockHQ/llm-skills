# Troubleshooting

> Verified against NVIDIA GPU Operator v26.7.1 (docs `troubleshooting`, `platform-support`, `release-notes`), 2026-10-11

First collect: `kubectl get pods -n gpu-operator -o wide`, `kubectl describe pod <p> -n gpu-operator`, driver and toolkit logs.
For a bug report upstream wants the output of `hack/must-gather.sh` (downloaded from the NVIDIA/gpu-operator repo; review it before running).

| Symptom                                                                       | Cause                                                                      | Fix                                                                                                                                                                    |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| All operand pods stuck in `Init`                                              | The driver daemonset is not healthy (operands wait for driver and toolkit) | `kubectl logs -n gpu-operator <driver-pod> -c nvidia-driver-ctr`; if `Init:Error`, `-c k8s-driver-manager`; check `dmesg`; check internet access for package downloads |
| `Failed to enable MSI-X` in logs, pods stuck in Init                          | `nouveau` kernel module loaded                                             | Denylist nouveau on the node OS (required with vGPU); reboot                                                                                                           |
| `no runtime for "nvidia" is configured`                                       | Toolkit did not register the runtime handler                               | Toolkit pod logs (`-c nvidia-container-toolkit-ctr`); containerd/CRI-O config (`containerd config dump`, `crio status config`); driver pod health                      |
| Validator crashing with `system not yet initialized`                          | NVSwitch node (DGX/HGX) needs Fabric Manager                               | In the driver pod `nvidia-smi -q` shows `Fabric State: In Progress`; check driver logs for fabric manager install and `/var/log/fabricmanager.log`                     |
| GFD `CrashLoopBackOff`, `driver rpc error: timed out`                         | Driver or hardware problem                                                 | `sudo dmesg \| grep -i -E 'NVRM\|Xid'` (for example Xid 79 "GPU has fallen off the bus"); reseat, drain, replace                                                       |
| Node shows fewer `nvidia.com/gpu` than installed                              | Device plugin marked a GPU unhealthy after a critical Xid                  | `kubectl logs -n gpu-operator <device-plugin-pod> -c nvidia-device-plugin` (look for `XidCriticalError`); fix hardware or reset the GPU                                |
| DCGM exporter `CrashLoopBackOff` connecting to `nvidia-dcgm:5555`             | Standalone DCGM enabled and traffic blocked                                | Allow pod-to-pod traffic in NetworkPolicies and security groups, or use the embedded DCGM                                                                              |
| Driver upgrade never progresses                                               | Drain or eviction blocked by pods or PDBs; policy limits                   | Check `nvidia.com/gpu-driver-upgrade-state` labels, `upgradePolicy`, PDBs, and pods blocking eviction                                                                  |
| Pods using GPUs fail after operator restart or driver pod restart             | Operands started before driver libraries were ready (fixed in 26.7.1)      | Upgrade to 26.7.1 or later; MIG Manager `ERROR_LIBRARY_NOT_FOUND` is the same issue                                                                                    |
| GFD cannot update NodeFeature with OwnerReferencesPermissionEnforcement       | Role lacked delete on NodeFeature (fixed in 26.7.1)                        | Upgrade to 26.7.1                                                                                                                                                      |
| Pods requesting `nvidia.com/gpu: 2` on a time-sliced node get no more compute | Replicas are shared, not proportional                                      | Set `failRequestsGreaterThanOne: true`; use whole GPUs or MIG                                                                                                          |
| CUDA init fails on RTX PRO 6000 Blackwell                                     | HMM in UVM                                                                 | Customize driver parameters to disable HMM; need driver 575.57.08 or later                                                                                             |
| Helm install blocked, Pod Security violations                                 | Namespace not `privileged`                                                 | `kubectl label --overwrite ns gpu-operator pod-security.kubernetes.io/enforce=privileged`                                                                              |
| RHEL 8 + containerd + SELinux errors                                          | containerd SELinux option                                                  | Set `enable_selinux=true` in containerd                                                                                                                                |
| Pod pending `0/N nodes available: insufficient nvidia.com/gpu`                | Plugin not ready, all GPUs allocated, node taints                          | `kubectl describe node`, check allocatable vs requests, tolerations                                                                                                    |
| Kernel update broke the driver                                                | Auto-updated kernel without a matching driver container                    | Pin kernels, disable unattended upgrades, consider precompiled driver containers                                                                                       |
