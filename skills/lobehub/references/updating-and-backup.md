# LobeHub: update, gateway upgrade, backup and restore

> Verified against LobeHub v2.2.19 (docs: self-hosting/server-database/docker-compose), 2026-10-11

## Backup first

```bash
cp .env ".env.bak.$(date +%F)"                                              # contains secrets: keep 0600
docker compose exec -T postgresql pg_dump -U postgres lobechat > backup.sql   # database name is LOBE_DB_NAME (default lobechat)
docker compose exec rustfs tar czf /tmp/backup.tar.gz /data && docker cp lobe-rustfs:/tmp/backup.tar.gz ./rustfs-backup.tar.gz
docker compose exec redis redis-cli BGSAVE
```

Restore the database with `docker compose exec -T postgresql psql -U postgres lobechat < backup.sql`. Store `KEY_VAULTS_SECRET` with the backup, or saved user keys cannot be decrypted. Treat all archives as secret.

## Update

```bash
# with a pinned tag: edit the tag in docker-compose.yml, then
docker compose pull && docker compose up -d
docker logs --tail 50 lobehub        # migration, then Ready
```

Migrations are run automatically from the image; upstream recommends a database managed by this deployment so schema stays in step. Read the release notes before jumping several versions.

## Upgrading an older Compose deployment

The current `docker-compose.yml` adds a gateway service. Before starting it:

1. `cp .env .env.bak` and download the new `docker-compose.yml`.
2. Add `AGENT_GATEWAY_PORT`, `DEVICE_GATEWAY_PORT`, `AGENT_GATEWAY_URL`, `DEVICE_GATEWAY_URL`, `GATEWAY_SERVICE_TOKEN` (`openssl rand -hex 32`) and `JWKS_PUBLIC_KEY` (the public half of `JWKS_KEY`, generated by the command in the upstream upgrade section) to `.env`.
3. If `JWKS_KEY` is still the old example (kid `6823046760c5d460`), replace the pair with a freshly generated one.
4. `docker compose up -d --force-recreate`.

Without these the `lobe-gateway` container restarts in a loop and `docker logs lobehub` prints an `ACTION REQUIRED` warning.

## Upgrading from 1.x

2.0 removed NextAuth, Clerk, `ACCESS_CODE` and client-database mode, and requires `AUTH_SECRET` and `JWKS_KEY`. Follow the NextAuth or Clerk migration guides in the docs and back up everything first.

## Neon / pg_search note

If you use Neon for the database, the docs describe a migration away from Neon's `pg_search`; self-hosted ParadeDB needs no change.
