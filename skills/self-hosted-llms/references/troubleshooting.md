# Troubleshooting

> Verified against llama-swap v263, LiteLLM v1.105.0, cloudflared 2026.10.0, earlyoom v1.9.0, huggingface_hub v2.2.0, 2026-10-11

Start with a status snapshot (`status.md`), then find the symptom. One row per lesson; the linked
reference has the detail.

## Symptom -> cause -> fix

| Symptom                                                                                           | Cause                                                                                                                                           | Fix                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node freezes or becomes unreachable during a download, build or long prompt; earlyoom never fired | earlyoom acts only when **both** available memory and free swap are below their minimums; with a large free swap the swap condition stays false | `EARLYOOM_ARGS="-m <pct> -s 100 ..."` so only memory decides; unquoted regexes (`memory-safety.md`)                                                                        |
| `hf download` dies partway inside a `systemd-run` scope; partial files                            | hf-xet's parallel download exceeds the scope's `MemoryMax` and is OOM-killed                                                                    | Larger cap, no `HF_XET_HIGH_PERFORMANCE` on serving nodes, `HF_HUB_DISABLE_XET=1` as fallback, re-run to resume (`memory-safety.md`, `models-and-weights.md`)              |
| Container cannot open weights; `find -xtype l` lists links; node-b fails while node-a works       | Shared HF blob store: repo `blobs/` entries are symlinks into the cache-wide `hub/blobs/`, which was not mounted or not copied                  | Mount the whole HF cache; rsync all of `hub/`; or re-download on that node; `HF_HUB_DISABLE_SHARED_BLOBS=1` for hand-copied models (`models-and-weights.md`, `cleanup.md`) |
| `Permission denied` writing the HF cache, logs or `/opt/llm-stack`; cleanup fails                 | Containers running as root left root-owned files on bind mounts                                                                                 | Confirm the paths, then `sudo chown -R llm:llm <path>`; run containers with `--user` where the image allows (`cleanup.md`, `host-setup.md`)                                |
| Dual-node model hangs at startup, version-mismatch or NCCL errors, worker crashes                 | node-b runs a stale image while node-a runs a locally built one with the same tag                                                               | Compare image IDs on both nodes, `docker save \| ssh node-b docker load` (`updating.md`, `hardware-dgx-spark.md`)                                                          |
| Every request returns **HTTP 530** (error 1033)                                                   | The tunnel was started with `nohup` (or by hand) and the process died; no connector                                                             | Run cloudflared as the systemd service with restart (`exposure-cloudflare.md`)                                                                                             |
| **HTTP 524** after about two minutes on a cold model or a large image                             | Cloudflare's proxy read timeout (125 s by default) expired before the origin answered                                                           | Stream with `sendLoadingState: true`, preload models, long jobs over the tailnet (`exposure-cloudflare.md`, `llama-swap.md`)                                               |
| LobeHub (or another client) shows all models with the same old date and a small context           | LiteLLM's `/v1/models` uses one placeholder `created` and has no context size                                                                   | Serve the enriched catalog behind Caddy forward_auth (`model-catalog.md`, `clients.md`)                                                                                    |
| Reasoning variant has no effect, errors, or thinking text leaks into the answer                   | Effort values differ per model; Qwen-style models need `chat_template_kwargs`; missing reasoning parser                                         | Per-model variants with llama-swap `setParamsByID`, `stripParams` where unsupported, set `--reasoning-parser` (`reasoning-effort.md`)                                      |
| After a `/v1/responses` call, unrelated requests fail on the same connection                      | The backend had no `/v1/responses` route; the error left pooled keep-alive connections broken                                                   | `use_chat_completions_api: true` on every chat entry; smoke test 6 (`litellm.md`)                                                                                          |
| sparkDash rejects requests through `dash.example.com`; or probes fail with 401                    | Host allow-list missing the custom domain; probes pointed at a key-protected port                                                               | `SPARKDASH_ALLOWED_HOSTS=dash.example.com`; probe llama-swap 8080 or the engine port (`monitoring-sparkdash.md`)                                                           |
| Wrapper or script waiting for a process to exit never finishes                                    | `pgrep -f <pattern>` matches the waiting shell itself, whose command line contains the pattern                                                  | Wait on `docker inspect -f '{{.State.Status}}'` (`assets/common.sh`, `adding-a-server.md`)                                                                                 |
| After an upstream recipe update the model fails to download or a different model loads            | Upstream changed the default `MODEL_ID`; the pinned revision belongs to the old repository                                                      | Pin model ID and revision together in `models.d/<id>.sh`; diff defaults on update (`updating.md`)                                                                          |
| A password shows up in a system file or shell history                                             | It was piped through `echo ... \| sudo tee <file>`                                                                                              | Remove it, rotate the password, use `sudo -v` interactively (`security.md`)                                                                                                |
| 502 `proxy error: EOF` after a streamed response from llama-server                                | Upstream closes keep-alive connections after streaming                                                                                          | `disableKeepAlives: true` on that llama-swap model (`llama-swap.md`)                                                                                                       |
| Model is killed during loading; requests fail after `healthCheckTimeout`                          | Load takes longer than `healthCheckTimeout`                                                                                                     | Raise it (900 s or more for large models) (`llama-swap.md`)                                                                                                                |
| Every model loads in turn every few minutes                                                       | Authenticated LiteLLM `/health` used as a probe, or `background_health_checks` on                                                               | Probe `/health/liveliness`; disable background checks (`litellm.md`)                                                                                                       |
| `nvidia-smi` shows `Memory-Usage: Not Supported` on DGX Spark                                     | Expected on the GB10 iGPU (unified memory)                                                                                                      | Use `free -h` and `/proc/meminfo` (`hardware-dgx-spark.md`)                                                                                                                |
| Tools never called; JSON appears in `content`                                                     | Engine started without its tool-call parser                                                                                                     | Set the engine's tool parser flags (engine reference)                                                                                                                      |
| `exec format error` when starting a container                                                     | amd64-only image on arm64                                                                                                                       | Use a multi-arch or arm64 image (`hardware-dgx-spark.md`)                                                                                                                  |
| 401 from `/v1/models` with a valid key, other routes work                                         | Caddy forward_auth points at the wrong upstream, or the key lacks access to `/v1/models`                                                        | Check `LLM_GATEWAY` in `llm-catalog.service`; test the key directly against `127.0.0.1:4000/v1/models` (`model-catalog.md`)                                                |
| Tailscale clients get certificate or reachability errors after months                             | Node key expired (180 days by default)                                                                                                          | Re-authenticate, or disable key expiry for the server node (`exposure-tailscale.md`)                                                                                       |

## Narrowing down a failing request

Test each hop on loopback, inside out, and stop at the first failure:

```bash
curl -s 127.0.0.1:<engine-port>/health                         # engine (port from `docker ps` / llama-swap logs)
curl -s 127.0.0.1:8080/upstream/<id>/health                    # through llama-swap
curl -s 127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"<id>","max_tokens":8,"messages":[{"role":"user","content":"hi"}]}'
# then LiteLLM (127.0.0.1:4000) and the public URL with a key: smoke-test.md
```

Logs: `curl -sN 127.0.0.1:8080/logs/stream/<id>`, `journalctl -u llama-swap -u litellm -u cloudflared -f`,
`docker logs --tail 200 <id>` (and `ssh node-b docker logs --tail 200 <id>-worker`).
