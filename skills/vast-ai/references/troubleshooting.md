# Vast.ai troubleshooting

> Verified against docs.vast.ai guides/serverless, guides/instances/connect/networking, guides/instances/storage/volumes, cli/reference (create-instance, search-offers), vastai CLI 1.8.3, 2026-10-11

Start with `vastai show instance <ID> --raw | jq` (look at `actual_status` and `status_msg`), then the instance logs (console **Logs**, or `vastai logs <ID>`; confirm with `--help`) and, for Serverless, the worker logs (eye icon in the dashboard).

| Symptom                                                         | Likely cause                                                                                            | Fix                                                                                                                                |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `vastai: command not found`                                     | venv not active, or install not on `PATH`                                                               | Activate the venv, or `python -m vastai` if supported, or reinstall (`pip install vastai`)                                         |
| Authentication or `401` style errors from the CLI               | Missing, wrong or deleted API key                                                                       | Re-export `VAST_API_KEY` or rewrite `~/.config/vastai/vast_api_key`; `vastai show user` should work                                |
| `429`                                                           | API rate limit                                                                                          | `--retry` (default 3) handles it; slow down loops; avoid polling faster than every few seconds                                     |
| Permission denied for a scoped key                              | Missing permission category                                                                             | Recreate the key with `instance_write`, `misc` or `user_read` as needed                                                            |
| `create instance` fails: offer no longer available              | Another user rented the offer                                                                           | Re-run `search offers` for a fresh id                                                                                              |
| SSH refuses the key                                             | Public key was not registered before creation                                                           | `vastai create ssh-key`, then recreate or add the key to the running instance via the console                                      |
| Instance stays `loading`                                        | Large image pulling, slow host, wrong image                                                             | Wait; watch logs; destroy and choose a host with higher `inet_down` and a verified datacenter                                      |
| Instance goes `exited` or `unknown`                             | Host problem, crash, or out of balance                                                                  | Check logs and balance; destroy and re-rent if it does not recover                                                                 |
| `start instance` fails or queues                                | GPU was rented by someone else while stopped                                                            | Destroy and create a new instance; do not rely on stop and start                                                                   |
| Cannot reach vLLM on port 8000                                  | Port not requested, wrong external port, server bound to `127.0.0.1`, or still loading                  | Add `-p 8000:8000` at creation; read `VAST_TCP_PORT_8000` or `show instance --raw`; start with `--host 0.0.0.0`; read the vLLM log |
| `Connection refused` on the mapped port                         | Model still loading or crashed                                                                          | `ssh` in and check `curl localhost:8000/health` and the vLLM log                                                                   |
| `401` from vLLM                                                 | `--api-key` set and the client sent another key                                                         | Use the vLLM key; check `os.environ/VLLM_API_KEY` in LiteLLM                                                                       |
| Gated model download fails (`401`/`403` from Hugging Face)      | No `HF_TOKEN`, or no access to the repo                                                                 | Set `HF_TOKEN` as an account env var and accept the model licence                                                                  |
| CUDA out of memory                                              | Model plus KV cache exceed VRAM                                                                         | Smaller `--max-model-len`, quantized model, or a larger GPU or more GPUs                                                           |
| Disk full during download                                       | `--disk` too small                                                                                      | Destroy and recreate with more disk; container storage cannot be resized                                                           |
| Volume cannot attach                                            | Volume lives on another machine, or instance is a VM                                                    | Create instances on the volume's machine only; volumes are Docker-only and local                                                   |
| Cannot delete volume                                            | An instance still uses it                                                                               | Destroy the instance first, then `vastai delete volume`                                                                            |
| Docker commands inside the instance fail                        | Docker-in-Docker is unsupported                                                                         | Use the image directly; do not run Docker inside                                                                                   |
| `--onstart-cmd` ignored or truncated                            | Over 16 KB, or a shell quoting error                                                                    | Move the script into a template or fetch it at start; test the command by hand                                                     |
| Serverless worker stuck in `Loading`                            | Missing `HF_TOKEN` for a gated model, or a bad `MODEL_NAME`                                             | Set `HF_TOKEN`; check `MODEL_NAME`, `VLLM_ARGS` and the worker log                                                                 |
| Serverless: no workers or long first response                   | All workers cold; first deploy takes about 3 to 5 minutes                                               | Wait for a `Ready` or `Stopped` (cold) worker; raise min workers or lower the cold threshold if latency matters                    |
| Serverless proxy returns errors for embeddings, images or audio | The OpenAI proxy only supports chat and completions                                                     | Call the worker directly via the SDK, or use another endpoint for those features                                                   |
| Serverless proxy: `parallel_tool_calls` error                   | Unsupported option                                                                                      | Remove it from the request                                                                                                         |
| Bill higher than expected                                       | Bandwidth not in `dph_total`, stopped instances still billing storage, endpoint defaults keep 5 workers | Destroy instead of stop, lower min workers, check offer bandwidth rates                                                            |
| Credits ran out and the instance vanished                       | $0 balance with no saved card destroys instances                                                        | Keep a balance buffer or a card on file                                                                                            |

## When logs say nothing

1. SSH in (`vastai ssh-url <ID>`) and run `nvidia-smi`, `df -h`, `ps aux | grep vllm`, `curl -s localhost:8000/health`.
2. Reproduce on a fresh, verified-datacenter offer. Marketplace hosts differ, and the same image may work on another host.
3. Capture instance id, host or machine id, time (UTC) and the error text before contacting Vast support. Never send the API key.
