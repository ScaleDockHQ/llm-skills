# Platforms and quants

> Verified against vLLM Muse Glimmer and Llama 4 Scout recipes, Meta Muse Glimmer developer docs (llama.cpp, vLLM, get-the-model), SGLang Muse Glimmer cookbook, NVIDIA Llama 4 Scout FP4 card, TensorRT-LLM Llama 4 guides, Ollama library pages, 2026-10-11

Rule of thumb: pick the quant Meta or the engine team documents for your hardware, then run `llm-evals` before shipping. Sizes below are checkpoint sizes from the pages linked in `metadata.json`; add KV cache and activation headroom.

## Muse Glimmer 30B (dense, 128K)

Quant notes:

- The Inferact NVFP4 build is W4A4 on 364 language-model projections; embeddings, `lm_head` and the vision tower stay unquantized (hence 25 GB, not ~15 GB). vLLM auto-detects it from `config.json` (`modelopt_fp4`), no extra flags.
- `RedHatAI/...-FP8-block` on RTX 5090 (sm120) fails with DeepGEMM `Unknown SF transformation` ([vllm#51884](https://github.com/vllm-project/vllm/issues/51884), open). Workaround from the recipe: `VLLM_USE_DEEP_GEMM=0 VLLM_MOE_USE_DEEP_GEMM=0`. With it, FP8 on 2x 5090 reached 177.6 tok/s at a rope-extended 262,144 context (outside Meta's tested range).
- Speculative decoding: vLLM uses `--speculative-config` with the `meta-models/Muse-Glimmer-30B-assistant` head (5.11 GB, `num_speculative_tokens` 15, `--max-num-seqs 32`); on a single 32 GB card the NVFP4 weights plus draft head OOM at init. llama.cpp uses `--spec-type draft-dflash` with the 1.6 GB GGUF draft. Quality is unchanged by design (verified drafts), but run the eval anyway.
- Context beyond 131,072 is a rope extension that the recipe tried only as an experiment; it changes memory arithmetic and `--gpu-memory-utilization 0.92` can OOM there.
- GGUF K-quants are the vendor's own; full-precision GGUF is not published (use safetensors with vLLM).

| Platform                       | Recommended                                                                                                                                                                                                                                                                                       | Evidence and caveats                                                                                                                                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **H100 80 GB**                 | Scout: vLLM or TensorRT-LLM with FP8 (`nvidia/...-FP8` or RedHat AI FP8). | **B200**                       | Scout NVFP4 (`nvidia/Llama-4-Scout-17B-16E-Instruct-FP4`, TensorRT-LLM; ModelOpt v0.33.0). Card: MMLU Pro 74 vs 75 BF16, GPQA 56 vs 57                                                                                                                                                            | FP4 needs compute capability 10.0                                                                                                                                                                                                            |
| 8x H100 / B200 node            | Maverick FP8 (`meta-llama/Llama-4-Maverick-17B-128E-Instruct-FP8`) with TensorRT-LLM (`--tp_size 8 --ep_size 1/2/8` by scenario) or vLLM TP=8                                                                                                                                                     | TensorRT-LLM README targets B200; Eagle3 speculative decoding guide exists                                                                                                                                                                   |
| **DGX Spark (128 GB)**         | Scout only, and only as a candidate: the NVFP4 build is listed at 65 GB. **Not verified**: the vLLM Scout recipe's hardware list has no GB10 row, and no source I found shows Llama 4 running on GB10. Maverick does not fit one node (smallest listed artifact: Ollama `llama4:128x17b`, 245 GB) | Prefer Muse Glimmer on Spark unless Llama 4 is mandatory                                                                                                                                                                                     |
| **Consumer RTX / CPU offload** | llama.cpp with Unsloth GGUF, e.g. `Llama-4-Scout-17B-16E-Instruct-UD-IQ2_XXS.gguf` with `-ot ".ffn_.*_exps.=CPU"` to keep experts in system RAM                                                                                                                                                   | Unsloth: `--ctx-size 16384 --temp 0.6 --min-p 0.01 --top-p 0.9`. A Fixstars test ran Q4_K_M on an RTX 6000 Ada at about 70 tok/s in vLLM and a bit slower in llama.cpp (blog, 2025)                                                          |
| Apple Silicon                  | Ollama `llama4:16x17b` (67 GB download; the unified-memory needed to run it was not verified)                                                                                                                                                                                                     | An MLX Llama 4 recipe was not verified; check `mlx` skill and `mlx-community` before promising it                                                                                                                                            |
| AMD MI300X-class, Xeon 6       | vLLM recipe has ROCm and CPU commands (8x MI300X: `VLLM_ROCM_USE_AITER=1 ... --max-model-len 32000`; Xeon 6: Docker `vllm/vllm-openai-cpu:latest-x86_64`, TP 4, `--max-model-len 8192`)                                                                                                           | From the recipe                                                                                                                                                                                                                              |

Context for Llama 4: the cards advertise 10M (Scout) and 1M (Maverick), but the engine docs and every recipe command read use far smaller `--max-model-len` / `--ctx-size` values (8K to 128K in examples). KV memory, not the model, is the limit. The vLLM issue [#46863](https://github.com/vllm-project/vllm/issues/46863) used `max-model-len 4000000` with FP8 KV on 4x A100, so very long contexts are reachable but unvalidated by recipes.

## Choosing quickly

1. Need one-GPU agent or coding model, 24 to 128 GB: Muse Glimmer NVFP4/GGUF.
2. Need the Llama 4 family on a datacenter box: Scout FP8 on Hopper, NVFP4 on Blackwell, via TensorRT-LLM or vLLM.
3. Need Llama 4 on a laptop or small GPU: Unsloth GGUF with expert offload, accept low speed.
4. Need old Llama 3.3 70B: any engine; 4-bit GGUF or AWQ via `model-quantization`.
