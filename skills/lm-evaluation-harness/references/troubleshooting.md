# lm-evaluation-harness: troubleshooting

> Verified against lm-evaluation-harness v0.4.13 (source: openai_completions.py, api_models.py, vllm_causallms.py; docs: interface.md, footguns.md), 2026-10-11

Turn on logs with `LMEVAL_LOG_LEVEL=DEBUG`. Print the first prompts with `--write_out`. Always inspect samples (`--log_samples`) before trusting a score.

| Symptom                                                                              | Cause                                                                                         | Fix                                                                                                              |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `NotImplementedError: Loglikelihood is not supported for chat completions`           | Multiple-choice or loglikelihood task on `local-chat-completions`                             | Use `local-completions` (needs prompt logprobs), the `vllm`/`hf` backend, or a generative variant of the task    |
| `LocalChatCompletion expects messages as list[dict]`                                 | `--apply_chat_template` missing                                                               | Add `--apply_chat_template`                                                                                      |
| `chat-completions require the --apply_chat_template flag` (OpenAI chat model type)   | Same                                                                                          | Add `--apply_chat_template`                                                                                      |
| `API key not found ... OPENAI_API_KEY` (`openai-*` types)                            | `openai-*` require the variable; `local-*` accept an empty one                                | `export OPENAI_API_KEY="$LLM_API_KEY"`                                                                           |
| 401/403 from the server                                                              | Wrong key or header                                                                           | Check `OPENAI_API_KEY`; custom header via `model_args` `header=`; test with `curl`                               |
| `Context length must be greater than 0` or odd `loglikelihood` failures              | Server returned no usable prompt logprobs, or tokenizer mismatch                              | Run the logprobs `curl`; set `tokenizer_backend=huggingface,tokenizer=<repo>` matching the served model          |
| `logprobs` is null in the `curl` check                                               | Server does not support `echo` with `logprobs` on `/v1/completions`                           | Use generative tasks only, or serve with an engine that supports it (vLLM does)                                  |
| Remote tokenizer auto-detection picks the wrong tokenizer on an authenticated server | The probe does not send `OPENAI_API_KEY`; it falls back to Hugging Face with the served name  | Pass `tokenizer_backend=huggingface,tokenizer=<repo-or-path>` explicitly                                         |
| Hugging Face 404 for the tokenizer repo                                              | Served model name is an alias, not a Hub repo                                                 | Set `tokenizer=<real repo or local path>`                                                                        |
| Scores far below published numbers                                                   | Different few-shot, chat template, `max_gen_toks`, answer filter; truncation; harness version | Match upstream settings for that task; raise `max_length` and `max_gen_toks`; read samples                       |
| GSM8K near zero, answers cut off                                                     | `max_gen_toks` default 256 too small for chain of thought                                     | `--gen_kwargs max_gen_toks=1024` (or the task's setting)                                                         |
| Empty or `None` responses                                                            | Content filter, server error, or reasoning returned outside `content`                         | Check the raw response; for reasoning models see `think_end_token` in `tasks.md`                                 |
| `<think>` text breaks answer extraction                                              | Reasoning trace not stripped                                                                  | `think_end_token="</think>"` (and `enable_thinking=True` on `vllm`/`hf`); ensure the delimiter reaches `content` |
| `ValueError: ... think_end_token is required when using enable_thinking=True`        | `enable_thinking` without a delimiter                                                         | Provide `think_end_token`                                                                                        |
| Run is slow against a server                                                         | `num_concurrent` is 1 by default; chat batch size is forced to 1                              | `num_concurrent=8` or more up to server capacity; `local-completions` can also use `batch_size`                  |
| Request timeouts                                                                     | Long generations or reasoning                                                                 | Raise `timeout` (source default 300 s) and `max_retries`                                                         |
| Out of memory with the `vllm` backend and `--batch_size auto`                        | Model's default context is huge                                                               | `max_model_len=4096` (or the length you need), lower `gpu_memory_utilization`                                    |
| `data_parallel_size` needs `ray`                                                     | Data parallel uses Ray actors                                                                 | `pip install ray`; download weights first with `data_parallel_size=1`                                            |
| `device` ignored with `vllm`                                                         | Backend ignores it                                                                            | `CUDA_VISIBLE_DEVICES=...`                                                                                       |
| Different results between `vllm` and `hf`                                            | Known upstream: vLLM can differ from the HF reference                                         | Use `hf` for reference numbers; upstream ships `scripts/model_comparator.py`                                     |
| A YAML task loses its newline stop sequence                                          | Single-quoted `'\n'` is a literal backslash-n                                                 | Use double quotes: `until: ["\n"]`                                                                               |
| Task import error for a missing module                                               | Task needs an extra                                                                           | Install the matching extra (`ifeval`, `math`, ...) from `pyproject.toml`                                         |
| Results identical across what should be different runs                               | `--use_cache` replayed responses                                                              | Remove `--use_cache` for comparison runs                                                                         |
| `--log_samples` writes nothing                                                       | No `--output_path`                                                                            | Set `--output_path`                                                                                              |
| Tasks refuse to run code or hub code                                                 | Safety confirmations                                                                          | `--confirm_run_unsafe_code`, `--trust_remote_code` only with the user's approval                                 |
| `o1`/GPT-5-style models reject `stop` or temperature                                 | OpenAI reasoning models; the harness drops `stop` and forces `temperature=1` for them         | Expected with `openai-chat-completions`; note it in the comparison                                               |

## Wrong-score triage order

1. Smoke run with `--limit 20 --log_samples`; read `arguments`, `resps`, `filtered_resps`, `target`.
2. Is the prompt right? Template applied once; system prompt and few-shot as intended.
3. Is the answer extracted? Compare `resps` with `filtered_resps`.
4. Is the endpoint faithful? Logprobs present; tokenizer matches; no server-side truncation (`max_length`).
5. Are you comparing like with like? Same version, task, few-shot, template, `gen_kwargs`, seed.

Contamination and benchmark-versus-product questions: install `llm-evals` (`npx skills add ScaleDockHQ/llm-skills --skill llm-evals`).
