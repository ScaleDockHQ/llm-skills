# Troubleshooting

> Verified against Ray 2.59.0 and KubeRay v1.7.1 (docs `serve/llm/troubleshooting`, `serve/production-guide/*`), 2026-10-11

Capture first: `serve status`, `ray status`, `kubectl describe rayservice <n>`, replica log tail.

| Symptom                                                                  | Cause                                                                                          | Fix                                                                                                                                           |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Replicas stay `STARTING` or "pending demand" in `ray status`             | No free GPU of the requested `accelerator_type`; worker group at `maxReplicas`                 | Check `ray status` resources and node labels, lower TP, fix `accelerator_type`, raise worker group max, enable `enableInTreeAutoscaling`      |
| 401 or "gated repo" when loading a model                                 | No Hugging Face token in the replica environment                                               | Provide `HF_TOKEN` through a Secret or `runtime_env` (never paste it into YAML); accept the model license on the Hub                          |
| Very slow first start                                                    | Each replica downloads weights from Hugging Face                                               | `HF_HUB_ENABLE_HF_TRANSFER=1` plus `hf_transfer`, mirror weights to a bucket (`model_source.bucket_uri`), bake into the image or use a volume |
| `ImportError: libcudart.so.12: cannot open shared object file` (NIXL EP) | Installed `nixl_ep` incompatible with the CUDA runtime and vLLM build (documented known issue) | Remove the incompatible package or install a `nixl_ep` that matches your CUDA runtime and vLLM; use the `ray-llm` image                       |
| Validation error on `disable_log_stats`                                  | Incompatible with `log_engine_metrics: true`                                                   | Remove it, or set `log_engine_metrics: false`                                                                                                 |
| Unsupported `accelerator_type` error                                     | Value not in the supported list                                                                | Use a listed type (`A10G`, `L4`, `H100`, ...); `A10` maps to `A10G`                                                                           |
| Requests queue, 503 or `BackPressureError`-style rejections              | `max_ongoing_requests` or `max_queued_requests` too small                                      | Raise `max_ongoing_requests` (LLM replicas batch), raise `max_replicas`, check upstream rate limits                                           |
| Prefix router shows no gain                                              | vLLM prefix caching off                                                                        | Set `engine_kwargs.enable_prefix_caching: true`; check hit-rate metrics                                                                       |
| `KVAwareRouter` errors or no routing                                     | Missing env vars or `ai-dynamo` not installed                                                  | Export the three env vars, `pip install "ai-dynamo>=1.4.0"`, use direct streaming (single model per app)                                      |
| LoRA request fails                                                       | `max_loras` differs from `max_num_adapters_per_replica`; wrong model string                    | Match them; query `<model_id>:<adapter_folder>`                                                                                               |
| Head restart drops all traffic                                           | No GCS fault tolerance                                                                         | Enable GCS FT (`references/kubernetes-kuberay.md`)                                                                                            |
| RayService update stuck, two clusters running                            | Cluster-level update waits for the new cluster to be ready; GPUs for both missing              | Free GPUs or wait; check the pending cluster's pods; `kubectl describe rayservice`                                                            |
| `serve deploy` against a RayService cluster reverts                      | Operator reconciles `serveConfigV2`                                                            | Edit the RayService, not the live cluster                                                                                                     |
| Prometheus has no `vllm` series                                          | `log_engine_metrics: false` or scrape only on head                                             | Scrape every pod's Ray metrics port                                                                                                           |

Help: Ray GitHub issues, Ray Slack and Discourse (links in the Ray troubleshooting page).
