# GGUF quantization: troubleshooting

> Verified against llama.cpp v0.6.0 and master b11556, 2026-10-11

| Symptom                                             | Likely cause                                                                       | Fix                                                                                                                                     |
| --------------------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `Model ... is not supported` / unknown architecture | Converter too old                                                                  | `git pull`/new tag, `pip install -U transformers`, check `--print-supported-models`                                                     |
| Converter killed or OOM                             | Eager loading                                                                      | Keep lazy mode (default), add `--use-temp-file`, free RAM; avoid `--no-lazy`                                                            |
| Missing tokenizer or `config.json` error            | Incomplete local dir                                                               | Re-download every file of the repo; custom tokenizers need their code files                                                             |
| Output chat is garbage or never stops               | Chat template or EOS metadata wrong                                                | Run `llama-server --jinja`; inspect with `gguf_dump.py`; fix template via `gguf_new_metadata.py` or reconvert from the latest converter |
| Vision prompt ignored                               | No `mmproj`                                                                        | Export `--mmproj`, pass `--mmproj` at serve time                                                                                        |
| `llama-quantize` refuses an already-quantized input | Requantize guard                                                                   | Quantize from the 16-bit GGUF; `--allow-requantize` only for experiments                                                                |
| `--include-weights` / `--exclude-weights` error     | Used together                                                                      | Pick one                                                                                                                                |
| Quant much worse than expected                      | No imatrix at low bpw, wrong calibration language, or a tensor type too aggressive | Add/improve imatrix; raise `--token-embedding-type`/`--output-tensor-type`; compare KLD to a stock type                                 |
| IQ1/IQ2 output unusable                             | Too few bits for this model                                                        | Move up a type; measure KLD                                                                                                             |
| `llama-quantize` runs out of RAM                    | Large tensors held in memory                                                       | Lower `--max-buffer-size` (default 8192 MiB); free RAM; cap with a memory-limited scope                                                 |
| imatrix very slow                                   | CPU only                                                                           | Add `-ngl`, `--no-ppl`, limit `--chunks`                                                                                                |
| imatrix OOM on GPU                                  | Server holding VRAM or unified memory                                              | Stop serving; reduce `-ngl`                                                                                                             |
| KLD run fills the disk                              | Logits file is 10s of GiB                                                          | Use a scratch disk, a shorter text, delete afterwards                                                                                   |
| Sharded input fails to load                         | Missing shard                                                                      | `llama-gguf-split --merge` or ensure all `-0000N-of-0000M` files are present                                                            |
| Server port unexpected                              | Default changed across builds                                                      | Pass `--port`; 9931 on b11556, 8080 on v0.6.0 and older                                                                                 |
| Upload rejected or slow                             | Hub limits or token scope                                                          | Split shards, check token write scope (`hf auth whoami`), retry per `hf upload --help`                                                  |
| Weird results only on CUDA vs CPU                   | Backend bug or build                                                               | Retest on CPU (`-ngl 0`), update, search upstream issues                                                                                |

If nothing matches, retry with the latest tag, then search the issue tracker at https://github.com/ggml-org/llama.cpp/issues for the architecture name and the exact error text.
