# EXL3 quantization: troubleshooting

> Verified against exllamav3 v1.6.1 (doc/convert.md, README.md, doc/env_vars.md), 2026-10-11

| Symptom                                                    | Likely cause                                                                        | Fix                                                                                                                |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `ModuleNotFoundError: exllamav3`                           | Library not in the active venv                                                      | Install it per the `exllamav3` skill; `python -c "import exllamav3"`                                               |
| Extension build fails or first import compiles for minutes | PyPI package has no prebuilt extension; missing CUDA toolkit, gcc or Python headers | Use a release wheel for your torch/CUDA/Python, or install the toolkit; first-import JIT is once per torch version |
| Unsupported architecture error                             | Not in the README table                                                             | Update ExLlamaV3; check the table; do not hand-edit configs                                                        |
| Job restarted from zero                                    | `-r` omitted                                                                        | Resume with `python convert.py -w <work_dir> -r`                                                                   |
| Output overwritten                                         | `-o` existed                                                                        | Use a fresh output directory per bitrate                                                                           |
| CUDA OOM during conversion                                 | GPU shared with a server or another job                                             | Stop the other process, `CUDA_VISIBLE_DEVICES`, then `-r`                                                          |
| Host RAM exhausted at the end                              | Huge shards                                                                         | Lower `-ss` (default 8192 MB); avoid `-ss 0` on large models                                                       |
| Work dir out of space                                      | Needs a full copy of the output                                                     | Move `-w` to a bigger disk; resume                                                                                 |
| Multi-GPU run not faster                                   | Slow PCIe, or too few tensors per layer                                             | Fewer devices; upstream says layers with fewer tensors than devices fall back to splitting encoding                |
| Recipe aborts with missing/unknown keys                    | Recipe built for another model or version                                           | Rebuild with `sc_optimize.py` for this model                                                                       |
| `sd_trace.py` not found                                    | Doc typo                                                                            | The file is `sc_trace.py`                                                                                          |
| Higher bitrate worse than lower                            | Bad run, wrong data, or bug                                                         | Re-evaluate on the same rows; reconvert; report upstream with the command                                          |
| Loaded model garbage in TabbyAPI                           | Version mismatch, wrong chat template                                               | Match library and TabbyAPI versions; check the template; `exllamav3` `troubleshooting.md`                          |
| Vision input ignored                                       | Vision tower missing or unquantized path not loaded                                 | Check `-vb`, the architecture's multimodal support, `util/convert_vision.py`                                       |
| `tie_word_embeddings` confusion                            | Converter unties them                                                               | Expected; output `config.json` has it false                                                                        |

If nothing matches: re-run with the latest release, add `-v` for debug output, and search https://github.com/turboderp-org/exllamav3/issues for the exact message before reporting.
