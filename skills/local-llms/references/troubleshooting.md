# Troubleshooting local LLMs

> Verified against Ollama v0.40.3, llama.cpp b11555, LM Studio 0.4.26, mlx-lm 0.32.0, 2026-10-11

Start with the discovery commands in `SKILL.md`, then find the symptom below. Read logs before changing anything:

| Runtime       | Logs                                                                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ollama        | macOS `~/.ollama/logs/server.log` · Linux `journalctl -u ollama --no-pager --follow --pager-end` · Windows `%LOCALAPPDATA%\Ollama\server.log` · `OLLAMA_DEBUG=1` for detail |
| LM Studio     | `lms log stream --source server`; `lms log stream` for model I/O                                                                                                            |
| llama-server  | stdout/stderr, `--log-file`, `-v`; systemd user: `journalctl --user -u llama-server -f`                                                                                     |
| mlx_lm.server | stdout; `--log-level DEBUG`                                                                                                                                                 |

## Symptom → cause → fix

| Symptom                                                   | Likely cause                                                                                                               | Fix                                                                                                                                                                                             |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client gets "connection refused"                          | Server not running, wrong port, or bound to a different interface                                                          | `curl -s http://127.0.0.1:<port>/v1/models`; check listeners (`lsof -nP -iTCP -sTCP:LISTEN`, `ss -ltnp`, `Get-NetTCPConnection -State Listen`). llama-server now defaults to **9931**, not 8080 |
| "address already in use"                                  | Two runtimes on one port (Ollama app + `ollama serve`, Windows + WSL2, mlx_lm.server and an old llama-server both on 8080) | Stop one, or give each its own `--port`                                                                                                                                                         |
| Very slow; `ollama ps` shows a CPU share; GPU idle        | Model + KV cache doesn't fit, so layers are offloaded                                                                      | Smaller quant, smaller context, `OLLAMA_KV_CACHE_TYPE=q8_0` / `-ctk q8_0 -ctv q8_0`; see `sizing.md`                                                                                            |
| Runs on the CPU even though it should fit                 | Wrong build (CPU tarball, x86_64 under Rosetta, CUDA zip without cudart), driver too old, or no `render` group             | `llama-server --list-devices`; `file $(command -v llama-server)`; update the driver; `sudo usermod -aG render,video "$USER"`                                                                    |
| NVIDIA GPU lost after suspend (Linux)                     | nvidia_uvm driver bug                                                                                                      | `sudo rmmod nvidia_uvm && sudo modprobe nvidia_uvm` (ask first)                                                                                                                                 |
| AMD GPU not detected                                      | Card not on the ROCm list                                                                                                  | Use Vulkan (Ollama default; llama.cpp `vulkan` build; LM Studio Vulkan runtime). On Linux, try `HSA_OVERRIDE_GFX_VERSION` as a last resort                                                      |
| Mac: model refuses to load or mlx-lm warns "requires ..." | Over the Metal wired-memory limit                                                                                          | Smaller quant first; otherwise raise `iogpu.wired_limit_mb` temporarily (ask; see `macos-apple-silicon.md`)                                                                                     |
| Mac becomes unresponsive, heavy swap                      | Model plus apps exceed RAM, or the wired limit is set too high                                                             | `sudo sysctl iogpu.wired_limit_mb=0`, quit apps, use a smaller model                                                                                                                            |
| Agent "forgets" instructions or truncates files           | Context window too small (Ollama defaults to 4k on <24 GiB VRAM)                                                           | `OLLAMA_CONTEXT_LENGTH=65536`, `lms load --context-length`, `llama-server -c`                                                                                                                   |
| Responses stop at about 512 tokens with mlx_lm.server     | `--max-tokens` default is 512                                                                                              | Start with a higher `--max-tokens`, or have the client send `max_tokens`                                                                                                                        |
| Tool calls returned as plain text, or JSON errors         | Chat template lacks tool support or is broken                                                                              | llama-server: keep `--jinja`, try `--chat-template-file`; update the runtime; use a model built for tools                                                                                       |
| `<think>` text leaks into answers                         | Reasoning not parsed                                                                                                       | llama-server `--reasoning-format`; mlx `--chat-template-args '{"enable_thinking":false}'`; client-side setting                                                                                  |
| 401 / "Invalid API Key"                                   | Key missing or wrong, or the client sends `x-api-key` vs `Authorization: Bearer` mismatched                                | Check the client's base URL and key source without printing the key; see `sharing-on-lan.md`                                                                                                    |
| 403 from Ollama through a proxy or tunnel                 | Host-header check while Ollama is bound to loopback                                                                        | Have the proxy send `Host: localhost:11434`                                                                                                                                                     |
| 503 from Ollama under load                                | Queue full (`OLLAMA_MAX_QUEUE`) or model loading                                                                           | Lower concurrency, raise `OLLAMA_NUM_PARALLEL` if memory allows                                                                                                                                 |
| 503 from llama-server `/health`                           | Model still loading                                                                                                        | Wait for `200`; large models on slow disks take a while                                                                                                                                         |
| First request after idle is slow                          | Model was unloaded (Ollama `OLLAMA_KEEP_ALIVE` 5m, LM Studio JIT TTL, llama-server `--sleep-idle-seconds`)                 | Raise keep-alive/TTL, or accept it to save memory                                                                                                                                               |
| Browser UI / extension blocked                            | CORS                                                                                                                       | Ollama `OLLAMA_ORIGINS`; LM Studio `--cors`; mlx `--allowed-origins`. Allow only the origins you need                                                                                           |
| Model download fails behind a proxy                       | Proxy env                                                                                                                  | Ollama: `HTTPS_PROXY` only (not `HTTP_PROXY`); gated HF repos need `HF_TOKEN`                                                                                                                   |
| Disk full                                                 | Model caches                                                                                                               | `ollama ls` / `ollama rm`; LM Studio My Models; `hf cache ls` / `hf cache rm` / `hf cache prune`; llama.cpp `-cl` lists its cache                                                               |
| Laptop speed drops over minutes                           | Thermal throttling or battery power                                                                                        | AC power, performance mode, cool-down; see `benchmarking.md`                                                                                                                                    |
| Garbled output with a new model                           | Runtime too old for the architecture                                                                                       | Update the runtime; llama.cpp usually supports new architectures first                                                                                                                          |

## Escalation

1. Reproduce with `curl` against `/v1/chat/completions` to rule out the client.
2. Reproduce with the smallest model in the same family to separate memory problems from other bugs.
3. Collect logs, versions, and the exact command, with keys redacted. Then search or file an issue upstream: ollama/ollama, ggml-org/llama.cpp, lmstudio-ai/lmstudio-bug-tracker, ml-explore/mlx-lm.
