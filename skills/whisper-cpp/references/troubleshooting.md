# whisper.cpp: troubleshooting

> Verified against whisper.cpp v1.9.5 (server.cpp and cli.cpp behaviour, README), 2026-10-11

| Symptom                                                                   | Cause and fix                                                                                                                                                                   |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Non-English audio comes back as English or garbage                        | Default language is `en`. Pass `-l auto` (CLI or server) or `-F language=nl`. Also check you are not using an `.en` model.                                                      |
| `failed to read audio data` / `failed to read WAV file` (HTTP 400)        | Input is not 16-bit WAV that the reader accepts. Start the server with `--convert` (needs ffmpeg), or convert first: `ffmpeg -i in.mp3 -ar 16000 -ac 1 -c:a pcm_s16le out.wav`. |
| `Failed to execute ffmpeg command` / `failed to process audio` (HTTP 500) | `--convert` is on but ffmpeg failed. Run `ffmpeg -version` as the service user, check `--tmp-dir` is writable (a systemd `ProtectSystem=strict` unit needs `ReadWritePaths`).   |
| Server exits immediately after printing `ffmpeg is not found`             | `--convert` with no ffmpeg on `PATH`; the check exits with status 0, which looks like a clean stop. Install ffmpeg or drop `--convert`.                                         |
| `no 'file' field in the request` (400)                                    | The multipart field must be named `file` (`-F file=@x.wav`), not `audio` or a raw body.                                                                                         |
| `404` on `/v1/audio/transcriptions`                                       | The server was started without `--request-path /v1/audio --inference-path /transcriptions`. Default route is `/inference`.                                                      |
| `503 {"status":"loading model"}`                                          | A `/load` is in progress. Retry; use `checkEndpoint` with `/health`.                                                                                                            |
| Process exits after `POST /load` with `model init failed`                 | The new model file could not be initialised and the server exits by design. Restart with a good `-m`.                                                                           |
| Model name in the client request has no effect                            | `model` is ignored by `/inference`. The loaded model answers. Use llama-swap model entries to select.                                                                           |
| Very long file fails with a dropped connection                            | Server read/write timeout is 600 s and not configurable by flag. Split the audio, or use `whisper-cli` for batch jobs.                                                          |
| Repeated phrases or "Thank you." on silence                               | Hallucination on silent stretches. Enable VAD (`--vad -vm <silero model>`), raise `-nth`, or pass `-nf`/lower `-tp`; see `cli.md`.                                              |
| Slow: GPU idle, CPU pegged                                                | The binary was built without the backend, or `-ng` was set. Check the `system_info` and backend init lines in the log; rebuild with `-DGGML_CUDA=1` etc. (`install.md`).        |
| GPU out of memory                                                         | Use a quantized or smaller model; stop other GPU processes; one server process per model.                                                                                       |
| CUDA arch error at build                                                  | Add `-DCMAKE_CUDA_ARCHITECTURES="<arch>"`.                                                                                                                                      |
| Container pull fails on arm64                                             | The registry tags were amd64 only on 2026-10-11 despite the README; build from source.                                                                                          |
| `docker run` model not found                                              | Mount the models directory and pass the container path to `-m`.                                                                                                                 |
| Anyone on the LAN can transcribe or call `/load`                          | The server has no auth and `/load` reads server-side paths. Bind `127.0.0.1` and put auth in the proxy (`serve-configuration.md`).                                              |
| OpenAI SDK errors on `/v1/models`                                         | whisper-server has no such route. Put llama-swap or LiteLLM in front, or skip the model listing call.                                                                           |
| Core ML model not used                                                    | Folder `ggml-<name>-encoder.mlmodelc` must sit next to `ggml-<name>.bin` and the build needs `-DWHISPER_COREML=1`; look for `Core ML model loaded` in the log.                  |
| `-ot` or `-d` seem ignored in the server                                  | The server uses form fields `offset_t` and `duration` instead (`api.md`).                                                                                                       |
