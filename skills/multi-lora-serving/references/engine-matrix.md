# Multi-LoRA Serving: per-engine flag matrix

> Verified against vLLM v0.31.0 (docs: features/lora; source: vllm/config/lora.py, engine/arg_utils.py), SGLang v0.5.21 (docs: lora, server_arguments), TensorRT-LLM v1.2.1 (docs: features/lora; source: llm_args.py), llama.cpp build b11556 (tools/server README, common/arg.cpp, convert_lora_to_gguf.py), TensorFold v1.0.7 (README), Ollama v0.40.3 (docs.ollama.com modelfile, import), ExLlamaV3 v1.6.1 (README), 2026-10-11

Every flag below was read in the upstream source or docs named above on the date above. Defaults are the upstream defaults at that version. Anything not found is marked "(unverified)" or "not documented".

## vLLM v0.31.0

LoRA works with any vLLM model that implements `SupportsLoRA`. Adapters are served per request.

| Need                          | Flag / env                                                                 | Default                               | Constraints and notes                                                                                                                                                                                                                                  |
| ----------------------------- | -------------------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Turn on                       | `--enable-lora`                                                            | off                                   | Required for everything below.                                                                                                                                                                                                                         |
| Register adapters at launch   | `--lora-modules name=path ...` or JSON `{"name","path","base_model_name"}` | none                                  | `path` can be a local dir or a Hugging Face repo id. JSON form adds `base_model_name`, which fills the model card `parent` field. Old `name=path` form still works.                                                                                    |
| Concurrent adapters per batch | `--max-loras N`                                                            | 1                                     | "Max number of LoRAs in a single batch" (must be 1 or more). Each slot reserves memory at `--max-lora-rank`. Base-model requests run in the same batch.                                                                                                |
| Max rank                      | `--max-lora-rank N`                                                        | 16                                    | Allowed values: 1, 8, 16, 32, 64, 128, 256, 320, 512. Set to the largest adapter rank; a much larger value "wastes memory and can cause performance issues". Error text when exceeded is rank-too-large style (exact string (unverified)).             |
| CPU cache                     | `--max-cpu-loras N`                                                        | none (effective default (unverified)) | Adapters stored in CPU memory. Must be at least `--max-loras`.                                                                                                                                                                                         |
| Adapter dtype                 | `--lora-dtype auto\|float16\|bfloat16`                                     | `auto` (base model dtype)             | A different dtype than training changes numerics: gate.                                                                                                                                                                                                |
| TP sharding                   | `--fully-sharded-loras`                                                    | false                                 | By default only half of the LoRA computation is sharded with TP. Likely faster at high sequence length, high rank or high TP size.                                                                                                                     |
| Restrict modules              | `--lora-target-modules o_proj qkv_proj ...`                                | all supported modules                 | Module name suffixes. Deployment-time restriction for performance.                                                                                                                                                                                     |
| Kernel grid                   | `--specialize-active-lora`                                                 | false                                 | Captures extra CUDA graphs per active-LoRA count (powers of 2 up to `max_loras`); costs startup time and memory. Only takes effect when `cudagraph_specialize_lora` is true.                                                                           |
| MoE adapters                  | `--enable-mixed-moe-lora-format`                                           | false                                 | Serve 2D (megatron-style, per-expert) and 3D (peft-style, fused) MoE adapters together. Declare `is_3d_lora_weight` per adapter: vLLM trusts it and a wrong value silently produces garbage. Shared-outer layout: `enable_moe_shared_loras` in config. |
| Multimodal                    | `--default-mm-loras '{"audio":"<id>"}'`, `--enable-tower-connector-lora`   | none, false                           | Default LoRA applied when a modality is present; only one LoRA per prompt. Tower and connector LoRA is experimental.                                                                                                                                   |
| Classification adapters       | `--max-lora-cls-labels N`                                                  | base head's `num_labels`              | PEFT sequence-classification adapters with `score` or `classifier` heads.                                                                                                                                                                              |

Per-request selection: send the adapter name as the `model` field of `/v1/completions` or `/v1/chat/completions`. Offline: `LLM(model=..., enable_lora=True)` with `LoRARequest(name, unique_int_id, path)`. `GET /v1/models` lists each adapter with `root` (artifact) and `parent` (base).

Runtime load and unload (set `VLLM_ALLOW_RUNTIME_LORA_UPDATING=True` before `vllm serve`):

```bash
curl -X POST http://127.0.0.1:8000/v1/load_lora_adapter -H 'Content-Type: application/json' \
  -d '{"lora_name":"sql_adapter","lora_path":"/path/to/adapter"}'
curl -X POST http://127.0.0.1:8000/v1/load_lora_adapter -H 'Content-Type: application/json' \
  -d '{"lora_name":"my-adapter","lora_path":"/path/to/adapter/v2","load_inplace":true}'   # replace same name
curl -X POST http://127.0.0.1:8000/v1/unload_lora_adapter -H 'Content-Type: application/json' \
  -d '{"lora_name":"sql_adapter"}'
```

Success replies from the docs: `Success: LoRA adapter 'sql_adapter' added successfully` and `... removed successfully`. Resolver plugins load adapters on first request for an unknown name: `VLLM_PLUGINS` with `lora_filesystem_resolver` plus `VLLM_LORA_RESOLVER_CACHE_DIR`, or `lora_hf_hub_resolver` plus `VLLM_LORA_RESOLVER_HF_REPO_LIST` (remote downloads are insecure per the docs). Docs warn the whole runtime-update feature "comes with security risks".

## SGLang v0.5.21

| Need              | Flag                                                                                                      | Default                      | Constraints and notes                                                                                                                                                                                                                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Turn on           | `--enable-lora`                                                                                           | false                        | Set automatically if `--lora-paths` is given.                                                                                                                                                                                                                         |
| Register adapters | `--lora-paths <PATH> \| <NAME>=<PATH> \| {"lora_name":..,"lora_path":..,"pinned":bool}` (space separated) | none                         | JSON form can pin an adapter to the GPU.                                                                                                                                                                                                                              |
| Slots per batch   | `--max-loras-per-batch N`                                                                                 | 8                            | "Maximum number of adapters for a running batch, including base-only requests", so one slot is used by the base. Lower it when memory is scarce.                                                                                                                      |
| CPU cache         | `--max-loaded-loras N`                                                                                    | none                         | Must be at least `--max-loras-per-batch`. With overlap loading it is capped at 2x `--max-loras-per-batch`.                                                                                                                                                            |
| Eviction          | `--lora-eviction-policy lru\|fifo`                                                                        | `lru`                        | When the GPU pool is full.                                                                                                                                                                                                                                            |
| Kernel backend    | `--lora-backend triton\|csgmv\|ascend\|torch_native`                                                      | `csgmv`                      | Chunked SGMV; the docs report 20% to 80% lower latency than `triton` on their benchmark. `--max-lora-chunk-size 16\|32\|64\|128` (default 16) applies to `csgmv`.                                                                                                     |
| Max rank          | `--max-lora-rank N`                                                                                       | inferred from `--lora-paths` | Set it explicitly when you will load larger adapters later.                                                                                                                                                                                                           |
| Target modules    | `--lora-target-modules q_proj k_proj ... all`                                                             | inferred from `--lora-paths` | Union over all adapters; `all` enables every supported module at a small speed cost. Set explicitly for dynamic loading.                                                                                                                                              |
| Overlap loading   | `--enable-lora-overlap-loading`                                                                           | false                        | Overlaps host-to-device adapter copies with compute. Needs pinned CPU memory. Docs report about 35% lower median TTFT in an adversarial benchmark; it can raise TTFT when adapter loads are short next to prefill, because multi-adapter prefill batching is reduced. |
| Tail latency      | `--lora-drain-wait-threshold SEC`                                                                         | 0.0 (off)                    | Drains a running adapter when another waits longer than this.                                                                                                                                                                                                         |
| MoE               | `--experts-shared-outer-loras`, `--lora-use-virtual-experts`                                              | auto-detected / false        | For MoE adapter layouts.                                                                                                                                                                                                                                              |
| Strict keys       | `--lora-strict-loading`                                                                                   | false                        | Mismatched or missing adapter keys raise an error.                                                                                                                                                                                                                    |
| Pinning           | `pinned` in `--lora-paths` JSON or load request                                                           | false                        | At most `--max-loras-per-batch - 1` pinned adapters.                                                                                                                                                                                                                  |
| DP attention      | `--tp N --dp-size N --enable-dp-attention --lora-backend triton`                                          | n/a                          | `--dp-size` must equal `--tp-size`; all adapters must be pinned; no overlap loading with DPA.                                                                                                                                                                         |

Per-request selection: OpenAI API with `model:adapter-name`; native `/generate` with `lora_path` (a list aligned with the input texts, `None` for the base).

Runtime: `POST /load_lora_adapter` with `{"lora_name","lora_path"}` and optional `"pinned": true`; `POST /unload_lora_adapter` with `{"lora_name"}`. For dynamic loading set `--max-lora-rank` and `--lora-target-modules` at launch, or later adapters must be the same shape or smaller. With data-parallel attention a load succeeds only if every rank succeeds; retry the unload of that name before reloading after a partial failure.

## TensorRT-LLM v1.2.1

LoRA is documented for the PyTorch backend, with HuggingFace and NeMo adapter formats and quantized models.

| Need                  | Config / API                                                                                                                                                           | Default               | Notes                                                                                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Config object         | `LoraConfig(lora_dir=[...], max_lora_rank=, max_loras=, max_cpu_loras=, lora_target_modules=[...], lora_ckpt_source="hf"\|"nemo", trtllm_modules_to_hf_modules={...})` | defaults (unverified) | `lora_target_modules` uses TensorRT-LLM names such as `attn_q`, `attn_k`, `attn_v`; map to HF names with `trtllm_modules_to_hf_modules`. |
| Serve                 | `trtllm-serve <model> --config config.yaml` with `lora_config:` keys (`lora_target_modules`, `max_lora_rank`)                                                          | n/a                   | The docs include a config-flag alias note; check `trtllm-serve --help` for the install.                                                  |
| Bench                 | `trtllm-bench --model $m throughput --dataset $d --config config.yaml` with `lora_config:`                                                                             | n/a                   | Docs example uses `max_loras: 8`, `max_cpu_loras: 8`, `max_lora_rank: 64`.                                                               |
| Cache sizing          | `PeftCacheConfig(host_cache_size=<bytes>, device_cache_percent=<fraction of free GPU memory>)`                                                                         | (unverified)          | Docs example: 1 GiB host cache, 10% device cache.                                                                                        |
| Per request (offline) | `llm.generate(prompts, sampling_params, lora_request=[LoRARequest("name", id, "/path")])`                                                                              | n/a                   | Each request names its adapter path and id.                                                                                              |
| Per request (server)  | `extra_body={"lora_request": {"lora_name", "lora_int_id", "lora_path"}}` on the OpenAI client                                                                          | n/a                   | From the docs example for `trtllm-serve`.                                                                                                |
| Runtime load/unload   | not documented                                                                                                                                                         | n/a                   | Adapters are supplied with requests; there is no separate load or unload endpoint in these docs.                                         |

## llama.cpp build b11556

| Need                   | Flag / endpoint                                                          | Default | Notes                                                                                      |
| ---------------------- | ------------------------------------------------------------------------ | ------- | ------------------------------------------------------------------------------------------ |
| Load adapters          | `--lora FNAME[,FNAME...]`                                                | none    | GGUF adapters. All load at scale 1.0. Comma-separated for several.                         |
| Load with a scale      | `--lora-scaled FNAME:SCALE[,FNAME:SCALE...]`                             | none    | Format must be `FNAME:SCALE`; a blend changes numerics: gate.                              |
| Load without applying  | `--lora-init-without-apply`                                              | off     | Loads adapters at scale 0; enable later via `POST /lora-adapters`.                         |
| List                   | `GET /lora-adapters`                                                     | n/a     | Returns `[{"id","path","scale"}]`. A disabled adapter shows scale 0.                       |
| Set global scales      | `POST /lora-adapters` with `[{"id":0,"scale":0.2},{"id":1,"scale":0.8}]` | n/a     | Overwritten by the per-request `lora` field. To disable an adapter set scale 0 or omit it. |
| Per request            | request field `lora`                                                     | n/a     | Overrides the global scales for that request.                                              |
| Convert a PEFT adapter | `convert_lora_to_gguf.py` in the llama.cpp repo                          | n/a     | See the `fine-tuning-llms` skill for the end-to-end conversion.                            |

llama.cpp sets the adapter list at launch and changes scales at runtime. The server README has no endpoint to add a new adapter file, so a new adapter needs a restart (as documented, not tested here).

## Other engines

| Engine            | Status                                                                                                                                                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TensorFold v1.0.7 | The README documents no LoRA or adapter flags. Treat as unsupported; to use an adapter, serve a merged checkpoint (gate it).                                                                                                                                         |
| Ollama v0.40.3    | The current Modelfile reference lists `FROM`, `PARAMETER`, `TEMPLATE`, `SYSTEM`, `LICENSE`, `MESSAGE`, `REQUIRES` and `CAPABILITY`; no `ADAPTER` instruction and no adapter section in the import docs. Whether older `ADAPTER` support still works is (unverified). |
| ExLlamaV3 v1.6.1  | LoRA support is not mentioned in its README (unverified in code and docs).                                                                                                                                                                                           |
