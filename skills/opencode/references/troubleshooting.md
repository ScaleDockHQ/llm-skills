# OpenCode with self-hosted endpoints: troubleshooting

> Verified against OpenCode v1.19.0 (docs: providers, models, config, cli, troubleshooting; GitHub issues checked 2026-10-11), 2026-10-11

Start with `scripts/check-endpoint.sh`. If it fails, the endpoint is the problem. Otherwise check `opencode auth list`, `opencode models <provider>` and the logs in `~/.local/share/opencode/log/` (`opencode --log-level DEBUG`).

| Symptom                                                                | Cause                                                                              | Fix                                                                                                    |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Provider or model missing from `/models`                               | Wrong key (`provider` vs `providers`), JSON error, or `disabled_providers`         | Validate with `jq . opencode.json`; match the generation (v1 `provider`, v2 `providers`).              |
| `/connect` credential not used                                         | Provider ID in `/connect` differs from the config key                              | Use the same ID; `opencode auth list` shows names.                                                     |
| `401` / `403`                                                          | Key missing, wrong env var name, or env not visible to the launcher                | `[ -n "${NAME:-}" ]` for the name in `{env:NAME}`; export where OpenCode starts.                       |
| `404` on `/chat/completions`                                           | `baseURL` missing or duplicating `/v1`, or the wrong wire format                   | `baseURL` ends in `/v1` once; chat engines use `@ai-sdk/openai-compatible`.                            |
| `404` on `/responses` or `/messages`                                   | Wrong package for the endpoint                                                     | `@ai-sdk/openai` only for Responses endpoints; `@ai-sdk/anthropic` only for Messages endpoints.        |
| `model not found`                                                      | Config key differs from the served ID                                              | List `GET /v1/models`; match case and tags exactly, or set `id`.                                       |
| Model answers but never edits files, shows tool JSON or XML            | Engine tool parser or template missing; `tool_call` flag wrong                     | Engine flags (`tool-calling-parsers`); `tool_call: true`.                                              |
| Tool calls fail on Ollama                                              | Context too small or silently truncated                                            | `OLLAMA_CONTEXT_LENGTH` 64k or more, check `ollama ps`; docs suggest `num_ctx` 16k to 32k at least.    |
| Stray text inside tool-call arguments                                  | Small or heavily quantized model (upstream #48119, closed)                         | Larger or coder-tuned model; update OpenCode and the engine.                                           |
| Context overflow errors from the server                                | `limit.context` higher than the server window, or missing                          | Set `limit.context` to the real window (`vllm --max-model-len`, `llama-server -c`, Ollama ctx).        |
| Compaction never happens, context errors first                         | No `limit` on the model                                                            | Add `limit.context` and `limit.output`.                                                                |
| Schema error: `limit` requires `context` and `output`                  | Only one of the pair given                                                         | Provide both.                                                                                          |
| Image paste does nothing                                               | `attachment` or `modalities.input` image missing, or the model is not multimodal   | `attachment: true`, `modalities.input` includes `image`, serve a vision model.                         |
| Request aborts mid-answer, or after a long wait                        | `chunkTimeout` (300000 ms default) or proxy idle timeout                           | Raise `options.chunkTimeout`/`timeout` (v2: `settings.*`); disable proxy buffering.                    |
| First request after idle fails                                         | llama-swap or Ollama loading the model                                             | Longer timeouts; keep the model warm (`keep_alive`, llama-swap `ttl`).                                 |
| `400` naming `reasoningSummary`, `reasoningEffort` or an unknown param | Variant option the backend rejects                                                 | Remove the variant; drop params in the gateway (LiteLLM `drop_params`).                                |
| Thinking text inside answers                                           | Engine reasoning parser off or `interleaved.field` mismatch                        | Enable the parser; set `interleaved.field` to the engine's field.                                      |
| Routing loop or no connection with a corporate proxy                   | TUI local server routed through the proxy                                          | `NO_PROXY=localhost,127.0.0.1`.                                                                        |
| TLS errors with a private CA                                           | Runtime does not trust the CA                                                      | `NODE_EXTRA_CA_CERTS=/path/ca.pem`.                                                                    |
| Config edit ignored                                                    | Higher-precedence file wins (project over global; inline and managed override all) | Check precedence: remote, global, `OPENCODE_CONFIG`, project, `.opencode`, inline, managed.            |
| `opencode` runs a different version than expected                      | v1 and v2 installs replaced each other                                             | `opencode --version`; reinstall the intended generation (`install-and-update.md`, `opencode-2.md`).    |
| Local models not offered (v2)                                          | Discovery disabled, wrong address, or server down                                  | Check the default address or set `settings.baseURL`; do not use `"plugins": ["-opencode.provider.*"]`. |

Escalate with: `opencode --version`, config with keys redacted, endpoint engine and version, check-script output, and the log excerpt.
