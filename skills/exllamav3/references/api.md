# TabbyAPI API

> Verified against TabbyAPI main (20d66e2: endpoints/ routers, docs/03.-Usage.md), 2026-10-11

Developer docs are autogenerated: `https://theroyallab.github.io/tabbyAPI` (OpenAI) and `/kobold`. Request parameters (samplers, `template_vars`, `return_progress`) are listed there; read them for the version you run.

## Authentication

Every endpoint except health and serviceinfo needs a key unless `disable_auth: true`. Send `Authorization: Bearer <key>`, or the `x-api-key` header (admin routes: `x-admin-key`) per `common/auth.py`. API key: generation and read endpoints. Admin key: load/unload, download, LoRA, templates, sampler override switching. `GET /v1/auth/permission` reports which level a key has. Keys live in `api_tokens.yml`; read them into env vars from a `0600` file, never print them.

## Endpoints (from the routers)

| Method and path                                            | Auth  | Purpose                                                            |
| ---------------------------------------------------------- | ----- | ------------------------------------------------------------------ |
| `GET /health`                                              | none  | 200 healthy, 503 with issues when unhealthy; does not load a model |
| `GET /.well-known/serviceinfo`                             | none  | service discovery document                                         |
| `GET /v1/models`, `/v1/model/list`                         | api   | loaded model (api key) or the whole model dir (admin key)          |
| `GET /v1/model`                                            | api   | currently loaded model and its parameters                          |
| `GET /v1/model/draft/list`                                 | api   | draft models                                                       |
| `POST /v1/model/load`                                      | admin | load a model, unloading the current one if different               |
| `POST /v1/model/unload`                                    | admin | unload and abort pending requests (emergency / free VRAM)          |
| `POST /v1/download`                                        | admin | download from Hugging Face into `model_dir`                        |
| `GET /v1/loras`, `/v1/lora/list`, `/v1/lora`               | api   | LoRA listing/loaded                                                |
| `POST /v1/lora/load`, `/v1/lora/unload`                    | admin | LoRA management                                                    |
| `GET /v1/model/embedding/list`, `/v1/model/embedding`      | api   | embedding models                                                   |
| `POST /v1/model/embedding/load`, `/unload`                 | admin | embedding model management                                         |
| `POST /v1/token/encode`, `/v1/token/decode`                | api   | tokenizer access                                                   |
| `GET /v1/templates`, `/v1/template/list`                   | api   | chat templates                                                     |
| `POST /v1/template/switch`, `/v1/template/unload`          | admin | change template                                                    |
| `GET /v1/sampling/overrides`, `/v1/sampling/override/list` | api   | sampler presets                                                    |
| `POST /v1/sampling/override/switch`, `/unload`             | admin | change preset                                                      |
| `POST /v1/completions`                                     | api   | text completions                                                   |
| `POST /v1/chat/completions`                                | api   | chat completions (tools, reasoning)                                |
| `POST /v1/embeddings`                                      | api   | embeddings (needs extras)                                          |
| `GET /props`                                               | api   | llama.cpp-style: model path, n_ctx, slots, chat template, vision   |
| `POST /apply-template`, `/v1/apply-template`               | api   | render chat messages to a prompt without generating                |

There is no `/v1/responses` and no Anthropic `/v1/messages`; put LiteLLM in front (see `integrations.md`). Kobold routes appear only when `api_servers` includes `Kobold`.

## Model load and unload

Load requests are ephemeral: `config.yml` model options do not apply unless named in `use_as_default`.

```bash
curl -s http://127.0.0.1:5000/v1/model/load \
  -H "Authorization: Bearer $TABBY_ADMIN_KEY" -H 'Content-Type: application/json' \
  -d '{
    "model_name": "Qwen3-32B-exl3-4.0bpw",
    "max_seq_len": 32768,
    "cache_size": 32768,
    "cache_mode": "8,8",
    "tensor_parallel": true,
    "draft_model": {"draft_model_name": "Qwen3-0.6B-exl3", "draft_rope_scale": 1.0}
  }'
curl -s -X POST http://127.0.0.1:5000/v1/model/unload -H "Authorization: Bearer $TABBY_ADMIN_KEY"
```

(`model_name` is the folder name under `model_dir`. The documented draft block uses `draft_model_name`; the cache mode string syntax `k,v` follows `config_sample.yml`.) The load call can take minutes for large models; it streams progress to the server log. Poll `GET /v1/model` and `/health`.

## Inline model loading

Set `model.inline_model_loading: true`. A request whose `model` names another folder under `model_dir` unloads the current model and loads it with defaults from that folder's `tabby_config.yml`. It is strict: unknown model gives 404, failed load 503, except names in `dummy_model_names` when `use_dummy_models` is on (they run on the loaded model). Leave it off when llama-swap decides what is loaded.

## llama.cpp-style conveniences

- `GET /props`: `model_path`, `default_generation_settings.n_ctx`, `total_slots`, `chat_template`, `modalities.vision`.
- `GET /v1/models` entries carry `meta` (`n_ctx_train`, `n_vocab`, `n_embd`); the loaded model adds `n_ctx` and `size` in bytes.
- `return_progress: true` on streaming requests adds `prompt_progress` chunks (`total`, `cache`, `processed`, `time_ms`).
- Responses carry a llama.cpp-style `timings` object (top-level on non-streaming, final chunk of a stream, or the usage chunk with `stream_options.include_usage`); only for single-generation requests.
- SSE keep-alive pings every 15 s (`sse_ping_interval`).

## Examples

```bash
curl -s http://127.0.0.1:5000/health
curl -s http://127.0.0.1:5000/v1/models -H "Authorization: Bearer $TABBY_API_KEY" | jq -r '.data[].id'
curl -s http://127.0.0.1:5000/v1/completions -H "Authorization: Bearer $TABBY_API_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"m","prompt":"Once upon a time,","max_tokens":64,"min_p":0.05}' | jq -r '.choices[0].text'
curl -s http://127.0.0.1:5000/v1/chat/completions -H "Authorization: Bearer $TABBY_API_KEY" -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"hi"}],"stream":true,"stream_options":{"include_usage":true}}'
```
