# Mistral known issues

> Verified against vLLM and llama.cpp GitHub issues and PRs, Hugging Face discussions and model cards, 2026-10-11

Issue state was read with `gh api` on 2026-10-11. "Closed" does not prove your build contains the fix, so
check versions before relying on it.

| Medium 3.5 forgets earlier context, quality drops at medium to long context (HF, GGUF, quants, finetunes)                                 | Transformers config had a wrong YaRN `mscale_all_dim` (1 instead of 0). Mistral fixed the official config on 2026-05-01. Anything converted or quantized from the old config is affected: re-download Unsloth's updated GGUFs or reconvert, then re-quantize or re-finetune                                                                                                                                                                                     | [HF discussion](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B/discussions/18), [Unsloth](https://huggingface.co/unsloth/Mistral-Medium-3.5-128B-GGUF/discussions/5)  |
| vLLM Medium 3.5 crashes at startup with `Mismatch in image token count ... ids=[0] and text=[1]` when `--reasoning-parser mistral` is set | `mistral-common` tokenizer inside the HF `PixtralProcessor` does not encode the `[IMG]` placeholder. Issue 45289 closed with the workaround: serve the consolidated (native) checkpoint with `--tokenizer_mode mistral --config_format mistral --load_format mistral`, and use a current vLLM, not a cached wheel. Fix PRs 45525 and 52643 were still open on 2026-10-11. Also hits NVIDIA's NVFP4 and plain HF-format loads when `mistral-common` is installed | [issue](https://github.com/vllm-project/vllm/issues/45289), [PR](https://github.com/vllm-project/vllm/pull/52643)                                                               |
