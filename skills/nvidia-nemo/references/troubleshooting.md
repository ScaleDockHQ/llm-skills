# NeMo troubleshooting

> Verified against NVIDIA-NeMo/Automodel v0.6.0, Megatron-Bridge v0.6.2, RL v0.7.0 (READMEs, docs/debugging.md, docs/about/installation.md, breaking-changes), 2026-10-11

| Symptom                                                            | Likely cause                                                                     | Fix                                                                                                                               |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `YAML config must specify a recipe target`                         | Automodel >= 0.4.0 requires a `recipe` section                                   | Add `recipe: TrainFinetuneRecipeForNextTokenPrediction` (or VLM recipe)                                                           |
| Old `python train.py` or `automodel finetune llm -c ...` fails     | 0.4.0 CLI change                                                                 | Use `automodel config.yaml [--nproc-per-node N]`; see docs/breaking-changes                                                       |
| Different loss or memory after upgrading Automodel to >= 0.5.0     | FSDP2 `reduce_dtype` now float32; frozen multimodal modules shard at root        | Set the old values explicitly in `distributed` only if you need the previous behavior                                             |
| OOM at step 0 on first backward or long sequences                  | Activation memory, cuBLAS/Triton autotune workspace                              | Lower `local_batch_size`, enable activation checkpointing in `distributed`, try one `prewarm:` option matching the failing kernel |
| `FileExistsError` resuming from an older checkpoint                | A published later-step checkpoint already exists in the dir                      | Use a fresh `checkpoint_dir` or remove the later checkpoints                                                                      |
| No consolidated HF weights after training                          | `save_consolidated: false`                                                       | Run the generated `model/consolidate.sh` or set `final`                                                                           |
| `ModuleNotFoundError: megatron` (NeMo RL)                          | Submodules not initialised                                                       | `git submodule update --init --recursive`                                                                                         |
| NeMo RL still uses old dependencies after editing `pyproject.toml` | Cached per-worker venvs                                                          | `NRL_FORCE_REBUILD_VENVS=true uv run ...`                                                                                         |
| `uv venv -p ...` weird interpreter errors (NeMo RL)                | Python is pinned by `.python-version`                                            | Re-run `uv venv` with no `-p`                                                                                                     |
| cuDNN / `cudnn.h` errors with `--extra mcore` on bare metal        | Missing cuDNN dev                                                                | Install cudnn, export `CUDNN_HOME` and `LD_LIBRARY_PATH` (docs/about/installation.md), or use the container                       |
| CUDA allocator fragmentation OOM (NeMo RL)                         | Large generation + training on the same GPUs                                     | `PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:64`, lower batch and sequence length, non-colocated generation                         |
| Ray cluster hangs waiting for resources                            | `cluster.num_nodes` / `gpus_per_node` differ from the allocation                 | Align them with `--nodes` and `--gres`                                                                                            |
| Megatron-Bridge model not supported                                | Architecture lacks a bridge, or it was removed (deprecated families go in 0.7.0) | `list_supported_architectures.py`; see docs/adding-new-models.md                                                                  |
| Megatron-Bridge import fails on Python 3.10/3.11                   | PyPI 0.6.2 needs Python >= 3.12                                                  | Use the container or a 3.12 environment                                                                                           |
| Dev Megatron-Core mismatch                                         | Submodule switched without `uv sync`                                             | Follow `scripts/switch_mcore.sh` instructions: `uv sync` (dev) or `uv sync --locked` (main)                                       |

Collect logs: `NRL_LOG_LEVEL=DEBUG`, `NCCL_DEBUG=INFO` for hangs, `nvidia-smi`, `ray status`. Never paste `HF_TOKEN` or `WANDB_API_KEY` into logs or YAML.
