# Troubleshooting

> Verified against vLLM v0.31.0 (docs `usage/troubleshooting.md`, `serving/distributed_troubleshooting.md`, `serving/parallelism_scaling.md`), 2026-10-11

Start with `vllm collect-env`, the first 100 log lines and the exact command. Then match the symptom.

| Symptom or error text                                                                                                           | Cause and fix                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Hangs at start, no progress                                                                                                     | Weights downloading or slow disk. Download first with `hf download` and pass the local path; test with `--load-format dummy` to see if loading is the problem; store models on local disk, not NFS                                               |
| `torch.OutOfMemoryError: CUDA out of memory`                                                                                    | Lower `--max-model-len`, `--max-num-seqs`, `--gpu-memory-utilization`; add `--kv-cache-dtype fp8`; use a quantized model; raise `--tensor-parallel-size`                                                                                         |
| `ValueError: ... the estimated maximum model length is N`                                                                       | KV cache cannot hold one full request; set `--max-model-len` to N or lower                                                                                                                                                                       |
| `ValueError: Free memory on device ... is less than desired GPU memory utilization`                                             | Another process holds GPU memory (a previous vLLM, another container). Stop it, or lower `--gpu-memory-utilization`. On unified-memory boxes see `combos/dgx-spark-dual-ray.md`                                                                  |
| `Model architectures ['X'] are not supported for now`                                                                           | Architecture missing in this vLLM; upgrade or check the supported-models list. Custom code models need `--trust-remote-code` (only for repos you trust)                                                                                          |
| `Model architectures ['X'] failed to be inspected`                                                                              | Read the log above it; usually a missing dependency or incompatible `transformers`                                                                                                                                                               |
| `RuntimeError: Failed to infer device type`                                                                                     | Wrong build for the hardware (CPU wheel on GPU host, no driver). Run with `VLLM_LOGGING_LEVEL=DEBUG`                                                                                                                                             |
| `CUDA error: the provided PTX was compiled with an unsupported toolchain` or `The NVIDIA driver on your system is too old`      | Update the driver, or in the official image add `-e VLLM_ENABLE_CUDA_COMPATIBILITY=1` (datacenter and select professional GPUs only)                                                                                                             |
| `ptxas fatal : Value 'sm_110a' is not defined for option 'gpu-name'` (CUDA 13, Triton)                                          | Use the toolkit's ptxas: `export TRITON_PTXAS_PATH=/usr/local/cuda/bin/ptxas`                                                                                                                                                                    |
| `no kernel image is available for execution on the device`                                                                      | Typical CUDA meaning: build not compiled for your GPU architecture. Not covered by upstream docs (unverified): try the newest wheel or the NGC image                                                                                             |
| `NCCL error: unhandled system error (ncclCommInitRank)`                                                                         | Missing `IPC_LOCK` capability or unmounted `/dev/shm` (GPUDirect RDMA setups); add the `IPC_LOCK` capability (`--cap-add=IPC_LOCK` in Docker; `securityContext.capabilities.add` in K8s) and mount a real `/dev/shm` (`--ipc=host`/`--shm-size`) |
| `NCCL WARN Cuda failure 217 'peer access is not supported between these two devices'`                                           | Driver bug on some PCIe machines; try `NCCL_CUMEM_HOST_ENABLE=0` or update the driver                                                                                                                                                            |
| Hang during multi-GPU startup                                                                                                   | Check inter-GPU comms with `NCCL_DEBUG=TRACE` and the troubleshooting script in the upstream docs; make sure `--ipc=host`. `NCCL_P2P_DISABLE=1` as a test on PCIe boxes is general NCCL advice, unverified for vLLM                              |
| `RuntimeError: An attempt has been made to start a new process before the current process has finished its bootstrapping phase` | Offline `LLM(...)` used without `if __name__ == "__main__":` guard (spawn method)                                                                                                                                                                |
| Crash near `self.graph.replay()`                                                                                                | CUDA graph error: add `--enforce-eager` to find the real failing op                                                                                                                                                                              |
| `torch/_inductor` errors                                                                                                        | Incompatible custom `triton`; reinstall matching versions or use `--enforce-eager` temporarily                                                                                                                                                   |
| `EngineCore encountered an issue` / `EngineDeadError`                                                                           | The real cause is earlier in the log. `/health` then returns 503                                                                                                                                                                                 |
| `No available node types can fulfill resource request` (Ray)                                                                    | Often a node with several IPs: set `VLLM_HOST_IP` so vLLM and Ray use the same address (upstream `distributed_troubleshooting.md`)                                                                                                               |
| Kubernetes pod restarts with `KeyboardInterrupt: terminated`                                                                    | Probe killed a slow start: `startupProbe` / higher `failureThreshold`                                                                                                                                                                            |
| Quality changed after upgrade                                                                                                   | Defaults now come from the model's `generation_config.json`. Compare with `--generation-config vllm`                                                                                                                                             |
| Tool call JSON or XML appears as plain `content`, or a parser-not-found error                                                   | Wrong or missing `--tool-call-parser` / `--reasoning-parser`, or a missing `--enable-auto-tool-choice` (`features.md`)                                                                                                                           |
| `unrecognized arguments: --swap-space` (and other flags)                                                                        | Removed or renamed flags; see `updating.md`                                                                                                                                                                                                      |
| 401 on `/v1/...`                                                                                                                | `--api-key` set; send `Authorization: Bearer <key>` (key from a `0600` file or env var)                                                                                                                                                          |
| 404 `The model X does not exist`                                                                                                | Request `model` differs from `--served-model-name`                                                                                                                                                                                               |

## Debug tools

- `VLLM_LOGGING_LEVEL=DEBUG`, `CUDA_LAUNCH_BLOCKING=1`, `NCCL_DEBUG=TRACE`, `VLLM_TRACE_FUNCTION=1` (very slow).
- Inter-node GPU check: the troubleshooting script in upstream `usage/troubleshooting.md#incorrect-hardwaredriver`
  run with `torchrun --rdzv_backend=static` (the doc explains why `static` rather than `c10d`).
- Ray: `ray status` and the Ray dashboard; see the Ray observability docs.
- Report bugs upstream with `vllm collect-env` output at https://github.com/vllm-project/vllm/issues.
- Do not paste logs that contain tokens or prompts into public issues; redact first.
