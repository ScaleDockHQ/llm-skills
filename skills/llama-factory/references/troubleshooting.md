# Troubleshooting LLaMA-Factory

> Verified against LLaMA-Factory v0.9.5, 2026-10-11

Start with `llamafactory-cli env`, the exact YAML and the full traceback. Upstream asks users to read its FAQ issue first: https://github.com/hiyouga/LLaMA-Factory/issues/4614. Entries marked (inferred) come from reading source and docs, not from reproducing the error.

| Symptom                                                                              | Cause and fix                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Dataset <name> not found` or KeyError on the dataset                                | Not registered. Add it to `dataset_info.json` in `dataset_dir` (default `./data`) and run from the repo root (`config-and-data.md`).                                                             |
| Loss falls but outputs ignore the data, or labels look empty                         | Wrong `columns`/`formatting` mapping. Print a row, compare with the mapping; ShareGPT roles must alternate (`human`/`observation` odd, `gpt`/`function_call` even).                              |
| Garbled or wrong chat format after training                                          | `template` differs between train and chat/export, or does not match the model family. Use one template everywhere.                                                                               |
| Reasoning model answers lack or always include `<think>`                             | `enable_thinking` differs between train and inference (`config-and-data.md`).                                                                                                                    |
| pip dependency conflict after upgrading `peft`, `trl`, `transformers` or `deepspeed` | The project pins ranges (`peft<=0.18.1`, `trl<=0.24.0`, `accelerate<=1.11.0`, `deepspeed<=0.18.4` at v0.9.5). Recreate the environment from the checkout; do not upgrade over it (`install.md`). |
| `ModuleNotFoundError: deepspeed` or deepspeed key ignored                            | Extra not installed: `pip install -r requirements/deepspeed.txt`; launch with `FORCE_TORCHRUN=1` (`multi-gpu.md`).                                                                               |
| Merged model quality collapses or merge errors                                       | Adapter was merged into a quantized base. Remove `quantization_bit` from the merge YAML and merge into the unquantized base.                                                                     |
| Training hangs at start on multiple GPUs (inferred)                                  | Rendezvous or NCCL problem: check `MASTER_ADDR`/`MASTER_PORT`, firewall, `NCCL_SOCKET_IFNAME`; try one GPU with `CUDA_VISIBLE_DEVICES=0` to isolate.                                             |
| OOM                                                                                  | Lower `cutoff_len` and batch size, raise accumulation, `quantization_bit: 4`, DeepSpeed ZeRO-3/offload (`training.md`, `multi-gpu.md`).                                                          |
| `Quantization dataset is necessary for exporting`                                    | `export_quantization_bit` set without `export_quantization_dataset` (raised in `ModelArguments`).                                                                                                |
| Gated model or dataset download fails                                                | Accept terms on Hugging Face and export `HF_TOKEN`; or use `USE_MODELSCOPE_HUB=1`. The README suggests `huggingface_hub<1.0.0` for the `huggingface-cli login` flow.                             |
| Web UI reachable from other machines                                                 | Default bind is `0.0.0.0` and there is no login; set `GRADIO_SERVER_NAME=127.0.0.1` (`export-and-serve.md`).                                                                                     |
| API answers without a key                                                            | `API_KEY` not set; set it and bind `API_HOST` privately.                                                                                                                                         |
| Old output overwritten                                                               | `overwrite_output_dir: true` in the examples; set `false`.                                                                                                                                       |
| Windows QLoRA fails                                                                  | Needs a pre-built Windows `bitsandbytes` wheel per the README.                                                                                                                                   |
| NPU QLoRA fails                                                                      | README says compile NPU `bitsandbytes` manually and set `double_quantization: false`.                                                                                                            |
