# Codex CLI with self-hosted endpoints: troubleshooting

> Verified against Codex CLI rust-v0.162.1 (docs: config-advanced, config-reference; GitHub issues checked 2026-10-11), 2026-10-11

Start with `scripts/check-endpoint.sh`. If it fails, the endpoint is the problem. If it passes and Codex still fails, run with the profile and read the first error line.

| Symptom                                                                    | Cause                                                                                                  | Fix                                                                                                                                      |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `404` on `/v1/responses`, or HTML back                                     | Endpoint is chat-only, or `base_url` lacks/duplicates `/v1`                                            | Use an engine with Responses or LiteLLM in front; `base_url` ends in `/v1` exactly once.                                                 |
| `wire_api = "chat"` rejected or ignored                                    | Chat mode no longer supported                                                                          | Use `wire_api = "responses"` (or omit it). Older blog posts are obsolete.                                                                |
| `401` / `403`                                                              | Key missing, wrong variable name, or key in a variable the GUI launcher cannot see                     | `[ -n "${NAME:-}" ]` for the `env_key` name; export where Codex starts; or use an auth command.                                          |
| Codex asks to sign in with ChatGPT                                         | `model_provider` not active (project config cannot set it; profile not selected)                       | Set it in the user `config.toml` or run `--profile <name>`; check the profile file name `<name>.config.toml`.                            |
| Startup warning about ignored keys in `.codex/config.toml`                 | `model_provider`, `model_providers`, `openai_base_url`, `profile`, `otel` in a project file            | Move them to `~/.codex/config.toml`.                                                                                                     |
| Error naming a reserved ID                                                 | Provider named `openai`, `ollama` or `lmstudio`                                                        | Rename (for example `local`); use `openai_base_url` to repoint built-in OpenAI.                                                          |
| `model not found` / unknown model                                          | `model` differs from the served name                                                                   | Read `GET /v1/models`; match case and tag exactly.                                                                                       |
| OpenAI models vanished or 404 `gpt-*` after enabling Ollama in the app     | App wrote top-level `model_provider` and `model_catalog_json` (openai/codex#30994, open at write time) | Remove those two top-level keys and use a profile.                                                                                       |
| `400` mentioning `reasoning`, `summary`, `verbosity` or an unknown field   | Backend rejects Responses parameters it does not implement                                             | `model_reasoning_summary = "none"`, `model_supports_reasoning_summaries = false`; drop unsupported params in LiteLLM (`drop_params`).    |
| `400 context_length_exceeded`, session stuck                               | Window overflow; local-provider auto-compaction cannot recover (#48870)                                | `/compact` by hand; set `model_context_window`, `model_auto_compact_token_limit`, `tool_output_token_limit` and raise the server window. |
| `400 Unterminated string` on every request after a long TUI session (vLLM) | Request bodies truncated mid-JSON in a long-lived process (#47723, open at write time)                 | Restart the TUI; update Codex and vLLM; report with versions if it persists.                                                             |
| `item type "compaction" is not supported` on resume or handoff             | Session history contains OpenAI-only items (#45393)                                                    | Start a new session on the custom provider.                                                                                              |
| Tools never run, model prints JSON or XML                                  | Engine tool parser or chat template missing                                                            | vLLM `--enable-auto-tool-choice --tool-call-parser`; llama.cpp `--jinja`; Ollama tools-capable model.                                    |
| MCP tools unavailable on llama-server                                      | MCP tools wrapped as `namespace` items strict backends cannot parse (#23186, #26977, #36942)           | Test without MCP; follow those issues for a flattening option; or use an engine/gateway that tolerates it.                               |
| Stream stalls, then retries, then fails                                    | Cold model load, proxy buffering, idle timeout                                                         | Raise `stream_idle_timeout_ms`; disable proxy buffering; keep the model warm (`keep_alive`, llama-swap `ttl`).                           |
| `Connection refused`, TLS errors                                           | Wrong host or port, firewall, private CA                                                               | Probe with curl; trust the CA at OS level; check `base_url` scheme.                                                                      |
| Thinking text in the answer                                                | Engine reasoning parser off                                                                            | vLLM `--reasoning-parser`; llama.cpp `--reasoning-format`.                                                                               |
| Codex chat hangs when Ollama is offline, even on OpenAI models             | Active provider points at an unreachable local host (#47789)                                           | Keep local setups in a profile, not in the default config.                                                                               |
| Slow turns, repeated full prefill                                          | No prefix caching, or the server evicts slots                                                          | Enable prefix caching on the engine (`vllm`, `llama-cpp` skills); keep history stable; avoid editing prior turns.                        |
| Config change ignored                                                      | Higher layer overrides it (profile, project, `-c`)                                                     | Remember the order: user, profile, project, command line. `codex --config key=value` for a test.                                         |

Issue numbers are openai/codex GitHub issues open when this skill was written; check their state before applying a workaround.

Escalate with: Codex version, provider block with keys redacted, endpoint engine and version, the check script output and the first error line.
